# 财务领域（finance）

> 定位：财务领域的**需求**（What）。实现设计见 `design/finance.md`。
> 编号规则：`R-财务-NNN`
> 范围界定：资金收付（多资金账户、收付款流水与收支分类、内部转账）+ 客户应收 + 供应商应付 + 收支汇总。**本领域为管理会计口径，不做复式记账**：不建会计科目表、不做借贷平衡与期末结转、不出资产负债表与现金流量表、不用于对外报税。**资金流水是本域唯一录入入口**：一笔钱只录一次，经营收支与资金收付两套口径分开展示、不重复计算。

### 口径声明（为什么不做复式记账）

- **定性**：本域是**单式流水账**——一笔钱一条流水、方向与分类表明性质；属管理会计口径，不是会计核算账
- **与复式记账的差别**：主流 ERP（SAP、Oracle、NetSuite、用友、金蝶等）采用复式记账——记账凭证（借贷两行、金额必相等）+ 会计科目表，产出总账、明细账、资产负债表、利润表、现金流量表。复式存在的三个硬需求：① 追踪钱从哪来、到哪去（银行账户、往来、存货都能对上）；② 编制对外报表（报税、贷款、审计）；③ 借贷不平衡即刻暴露录入错误
- **本场景取舍**：自家小厂自建系统，无审计、无对外报表、无贷款报表需求；上复式需科目表、凭证、期末结转，录入成本翻数倍且需专业会计参与设计。故**当前不引入复式**，采用与小微企业实际一致的「流水 + 收支分类」
- **明示局限**：不出资产负债表与现金流量表、不做借贷平衡校验、不做银行对账、不能直接用于报税
- **三件执行口径**：
  1. **单轨录入**：全部资金往来只在资金流水登记一次；销售单现结由源单自动派生收款流水，不重复录入
  2. **分类收口**：流水按收支分类组织——收款为销售回款 / 其他收入 / 借款，付款为采购付款 / 工资 / 费用 / 资产购置 / 还款；分类决定是否计入经营收支
  3. **混合口径**：销售收入与采购支出按应计（单据确认即计入，含赊销 / 赊购）；其余收入与支出按实际收付计入；经营收支不等于现金流入流出
- **金额与指标口径**：流水金额恒为正数、方向决定增减；经营收支中收入项与支出项分别按正数展示，净额 = 总收入 − 总支出（不称「净利润」，避免与会计核算的利润混淆）
- **升级路径**：未来若需对外报表（报税、贷款、审计），按 `2-adr.md` 新增 ADR 决策引入复式记账（科目表 + 凭证），本流水可平移为凭证的辅助记录

## R-财务-001：收支汇总

调研依据：`.战略与经营/01第一阶段规划/业务调研-财务台账.md`（原飞书三表 + 2026-11-10 架构讨论结论）。

### 口径声明

- **销售按应计**：销售收入 = 期间销售单合计，现结单取实收金额、赊销单取合计金额；含赊销，不等于现金流入
- **采购按应计**：采购支出 = 期间采购单合计，现结单取实付金额、赊购单取合计金额；含赊购，不等于现金流出
- **其余按收付**：其他收入、工资、费用按期间资金流水的实际收付计入
- **排除项**：销售回款、采购付款、借款、还款、资产购置、内部转账均不计入经营收支——销售回款与采购付款的损益已由单据计入，再算重复；其余只改变资金位置或负债，不构成经营损益
- **净额** = 总收入 − 总支出；不称净利润

### 指标

- 总收入 = 销售收入 + 其他收入
- 总支出 = 采购支出 + 工资 + 费用
- 净额 = 总收入 − 总支出
- 分类小计固定输出六项：销售收入、其他收入、采购支出、工资、费用、净额（无数据为 0）
- 条数 = 期间销售单数 + 期间采购单数 + 计入经营收支的流水条数

### 页面设计

按 `product/平台布局.md` 页面模式规范执行：

- **收支汇总（聚合页，页内两个 Tab）**：
  - Tab 1「经营收支」：总收入、总支出、净额三张指标卡 + 分类小计表；说明区为同一段小字——定位句「看这段时间生意赚了多少：收入按销售单、采购按采购单确认（赊销赊购都计入），工资费用按实付计入，所以净额不等于手里的现金」后接本期条数（N 张销售单、M 张采购单、K 条收支流水），右侧只放「分类口径说明」按钮（打开口径说明弹窗）；
  - Tab 2「资金收付」：期间收款、期间付款、净流入三张期间卡 + 「当前资金总额 · 此刻」卡，四卡同排；资金总额卡以左侧竖线、浅底与「此刻」标注和期间卡区分，并注明「不随日期筛选变化」；下方为各账户余额列表（账户编号、名称、类型 / 渠道、当前余额、状态，不展示期初余额）；说明区为定位句「看这段时间钱怎么动：收款与付款按流水实际发生计入，内部转账不算；净流入 = 收款 − 付款」；
  - Tab 写入 URL（`?tab=funds`），默认 Tab 1；两个 Tab **共用一份日期筛选**，切换 Tab 保留已查询区间，未点查询的输入不保留。
- **口径说明弹窗（弹窗说明，只读）**：入口为 Tab 1 说明区的「分类口径说明」；三组内容——① 怎么算：总收入 = 销售收入 + 其他收入，总支出 = 采购支出 + 工资 + 费用，净额 = 总收入 − 总支出；销售收入取自销售单（现结取实收、赊销取合计），采购支出取自采购单（现结取实付、赊购取合计），工资与费用取自流水；② 五个分类各是什么：销售收入（主营，来自销售单）、其他收入（卖废料、零星加工费）、采购支出（原木，来自采购单）、工资（人工）、费用（电费、运费、维修、房租等其余经营开支）；③ 为什么不含其余分类：销售回款与采购付款（损益已由销售单 / 采购单计入，再算重复）、借款与还款（负债增减，不是赚或花）、资产购置（买设备是资产转换）；收尾一句：净额回答「赚了多少」，不等于「进来多少现金」，现金看资金收付 Tab；底部只有「关闭」。
- **资金收付口径说明弹窗（弹窗说明，只读）**：入口为 Tab 2 说明句右侧的「资金口径说明」；与经营收支弹窗同构；三组内容——① 怎么算：期间收款 / 期间付款 / 净流入 = 收款 − 付款 / 资金总额 = 各账户此刻余额合计；② 净流入为什么不等于资金总额：前者是区间增量，后者是累计存量（期初 + 全部历史净流入），两者相差期初余额与区间之外的净流入；③ 哪些钱进、哪些不进：收款侧销售回款 / 其他收入 / 借款，付款侧采购付款 / 工资 / 费用 / 资产购置 / 还款，内部转账不计入；并说明账户余额 = 期初 + 收 − 付 + 转入 − 转出，停用账户仍计入总额、已删除账户不计入；收尾一句：这一页回答「钱怎么动、现在手里有多少」，赚没赚看经营收支 Tab；底部只有「关闭」；内容超出视口时弹窗内部滚动。
- **移动页（移动 Web `/m`，适老化）**：入口 = `/m` 首页「资金」卡片 → `/m/finance` 二级页 →「收支汇总」；顶部为分段按钮「经营收支 / 资金收付」（高 48px、选中实心，替代 PC 页内 Tab，写入同一 `?tab=funds`）；日期筛选为「日期从 / 至」两个整行控件 + 查询 / 重置大按钮，各页独立、不跨页共享；内容一律单列纵向——指标卡纵向堆叠（标签用 label 角色、数值用 numeric 强调变体），经营收支为三卡 + 分类小计单列行（分类 —— 金额，净额加粗），资金收付为期间三值 + 「当前资金总额 · 此刻」突出卡（竖线 + 浅底）+ 账户余额卡片行（账户名 + 当前余额 + 启用状态，不显示编号与渠道）；口径说明入口复用两个 PC 弹窗（宽度自适应、内容内部滚动）；不出现表格、横向滚动与多选。
- 数据来源：销售单由 order 域只读聚合、采购单由 purchase 域只读聚合；其余全部取自资金流水的收支分类；本页不落快照、实时计算。

## R-财务-002：资金收付与应收

调研依据：2026-11-12 财务域扩展讨论结论（多账户、承兑、内部转账、客户欠款口径）。

### 口径声明（经营收支与资金收付分层）

- 资金流水记录「钱实际怎么走的」，是财务域**唯一录入入口**；
- **收款不是收入、付款不是成本**：销售回款只冲减客户欠款，采购付款只冲减供应商应付；其他收入与费用按分类计入经营收支，采购成本按采购单计入；两套口径分开展示、不重复计算；
- 内部转账只是账户之间搬钱，**不计入收支统计**；
- 管理会计口径：不做复式记账、不做银行对账、不做逐张票据台账（承兑处理见下）。

### 资金账户

| 字段 | 口径 |
| --- | --- |
| 账户编号 | 系统生成（AC + 5 位流水，如 AC-00001），只读、永不复用 |
| 名称 | 手填（如「对公账户」「李四个人卡」「承兑票据」） |
| 类型 | 对公 / 对私 |
| 渠道 | 由类型级联：对公 = 银行 / 承兑汇票；对私 = 银行 / 微信 / 支付宝 / 现金 |
| 期初余额 | 建账时的余额，2 位小数，非负 |
| 启用状态 | 启用 / 停用 |

- 类型在前、渠道在后；渠道只显示当前类型允许的选项；切换类型时若渠道非法，自动重置为「银行」；
- 服务端校验类型与渠道组合，拒绝「对公 + 微信」「对私 + 承兑汇票」等非法组合；
- 原「票据」类型取消，历史票据账户迁移为「对公 + 承兑汇票」；
- 余额 = 期初 + 收款 − 付款 + 转入 − 转出，实时计算、不落库；
- 账户可删除（软删除）：删除后不再出现在账户列表与新建流水的下拉中，历史流水保留并显示当时的账户名称，编号不回收；
- 停用账户不出现在新建流水的账户下拉中，历史流水不受影响；启用 / 停用 / 删除均为列表行内操作。

### 资金流水

| 字段 | 口径 |
| --- | --- |
| 流水编号 | 系统生成（CF + 5 位流水，如 CF-00001），只读、永不复用 |
| 方向 | 收款 / 付款 / 内部转账 |
| 发生日期 | 手填，默认当天 |
| 金额 | 正数、最多 2 位小数；增减由方向决定 |
| 资金账户 | 必选；内部转账时为转出账户 |
| 转入账户 | 仅内部转账必填，且不能与转出账户相同 |
| 收支分类 | 收款：销售回款 / 其他收入 / 借款；付款：采购付款 / 工资 / 费用 / 资产购置 / 还款；内部转账无分类 |
| 客户 | 仅「销售回款」必选（按客户总欠款收款，不挂销售单）；其他收入、借款与付款不挂客户 |
| 供应商 | 仅「采购付款」必选（按供应商总应付付款，不挂采购单）；其他收款、付款与内部转账不挂供应商 |
| 方式 | 由资金账户渠道自动推导（银行 / 微信 / 支付宝 / 现金 / 承兑汇票），只读 |
| 备注 | 付款写付给谁、付什么（如「电费」「配件供应商」）；承兑写票号与到期日 |
| 来源 | 手工 / 销售单 / 采购单，只读 |

- **分类决定口径**：销售回款、采购付款、借款、还款、资产购置、内部转账不计入经营收支；其他收入、工资、费用计入；
- **源单流水只读**：销售单现结派生的收款流水、采购单现结派生的付款流水，在资金流水页不可编辑或删除，必须回源单操作；
- 手工流水可新建、编辑、删除（软删除），余额随流水变化自动回退；
- **承兑**按「票据账户 + 承兑方式 + 备注票号」处理，不做逐张票据台账；
- 未收未付的其他收支不单独登记，等实际收付时记一笔流水（应付待采购域另立）。

### 一次录入、另一侧自动派生

| 业务入口 | 录入内容 | 自动派生 |
| --- | --- | --- |
| 销售单现结 | 现结开关 + 收款账户 + 实收金额（默认合计、可改） | 收款流水（分类 = 销售回款、挂客户、源单 = 销售单、备注单号） |
| 销售单赊销 | 仅销售单 | 不生成流水；后续回款走手工收款流水（分类 = 销售回款、挂客户） |
| 采购单现结 | 结算方式 = 现结 + 付款账户 + 实付金额（默认合计、可改） | 付款流水（分类 = 采购付款、挂供应商、源单 = 采购单、备注单号） |
| 采购单赊购 | 仅采购单 | 不生成流水；后续付款走手工付款流水（分类 = 采购付款、挂供应商） |
| 内部转账 / 借款 | 仅资金流水 | 不进入经营收支 |

- 源单唯一：同一销售单或采购单最多派生一条流水，防重复；
- 编辑源单：流水同步金额、日期、账户、客户 / 供应商；
- 取消现结或删除源单：派生流水一并软删；
- 抹零 / 约整：现结实收与销售单合计的差额作「折让 / 抹零」，只作单据信息，不进收支汇总；实收大于合计时差额为预收；采购现结实付与合计的差额同理，作折让，不进应付与经营收支。

### 应收（客户欠款）

- 欠款 = 期初欠款 + 累计销售 − 累计收款；累计销售对**现结单取实收金额**、对赊销单取合计金额，只统计系统内销售单；
- 累计收款 = 挂该客户的销售回款流水合计，只统计系统内流水；
- 期初欠款 = 客户档案手填的上线前净欠款（≥ 0、两位小数、默认 0），只作欠款基数，不计入累计销售与经营收支；
- 欠款为负显示为「预收」，不截断；
- **历史回款不补录**：补录会流入某个资金账户，凭空增加账户余额与资金总额；历史往来只用期初欠款净额表达；
- **不做账龄、不做单笔核销**；收款按客户总欠款冲减；
- 客户列表只展示「欠款」，客户详情展示「期初欠款（非 0 时）、累计销售、累计收款、欠款」。

### 汇总

资金口径指标（期间收款、期间付款、净流入、当前资金总额、各账户当前余额）与页面归 `R-财务-001` 的 Tab 2，本节不重复定义。

### 页面设计

## R-财务-004：应付（供应商欠款）

调研依据：`.战略与经营/01第一阶段规划/业务调研-采购单.md`（2026-11-14）。

### 口径

- 应付 = 期初应付 + 累计采购 − 累计付款；
- 累计采购对**现结单取实付金额**、对赊购单取合计金额，只统计系统内采购单；
- 累计付款 = 挂该供应商的采购付款流水合计，只统计系统内流水；
- 期初应付 = 供应商档案手填的上线前净应付（≥ 0、两位小数、默认 0），只作应付基数，不计入累计采购与经营收支；
- 应付为负显示为「预付」，不截断；
- **历史付款不补录**：补录会流入某个资金账户，凭空减少账户余额与资金总额；历史往来只用期初应付净额表达；
- **不做账龄、不做单笔核销**；付款按供应商总应付冲减；
- 供应商列表只展示「应付」，供应商详情展示「期初应付（非 0 时）、累计采购、累计付款、应付」。

### 页面设计

- 应付在供应商列表与详情展示，页面归属 supplier 域（见 `product/supplier.md` R-供应商-001），本节只定义取数口径；
- 资金流水的供应商维度、采购付款必选供应商、采购现结派生付款流水，见 `R-财务-002`；
- 数据来源：累计采购对采购单只读聚合，累计付款对资金流水只读聚合，期初应付取供应商档案；本域不落快照、实时计算。
