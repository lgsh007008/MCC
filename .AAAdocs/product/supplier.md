## R-供应商-001：供应商档案与期初应付

### 口径声明

- 供应商是长期往来实体，一供应商一档案；采购单必须挂供应商。
- 档案只存**录入型数据**（名称、联系信息、期初应付、状态、备注），不存累计采购、累计付款、累计应付——三项由 finance 实时聚合（`R-财务-004`），避免第二份真相。
- **期初应付**是系统上线前已发生的净应付，由使用者手填：非负、两位小数、默认 0；历史付款不补录（理由同客户期初欠款：补录会流入资金账户、虚增账户余额与资金总额）。
- 期初应付只作应付基数，不计入累计采购、不计入经营收支。
- 已知取舍：历史预付暂无法表达，按 0 处理。

### 字段

| 字段 | 口径 |
| --- | --- |
| 供应商编号 | 系统生成 `SP-#####`，只读、永不复用 |
| 供应商名称 | 必填，≤100 字；不建唯一索引，重名只提示不阻断 |
| 联系方式 | 单行文本（电话、微信、地址等混合），≤200 字，可空 |
| 期初应付 | 非负、两位小数、默认 0；新建与编辑均可改，改后应付即时重算 |
| 状态 | 启用 / 停用 |
| 备注 | ≤500 字，可空 |
| 创建日期 | 创建时间，只读 |

### 页面设计

- **供应商列表（`/admin/suppliers`）**：筛选 = 名称（模糊）+ 状态；列 = 编号、名称、联系方式、应付、状态、创建日期；创建日期表头可切换正 / 倒序（默认倒序、切换后回第 1 页），其余列不排序；行操作 = 查看 / 编辑 / 停用（启用）/ 删除；首列多选与批量启用 / 批量停用 / 批量删除按平台列表页规范；列表**只展示应付**一列金额，累计采购与累计付款进详情，避免列过多。
- **新建 / 编辑表单**：新建与编辑共用；编号始终渲染——新建只读占位「系统生成」，编辑只读真实编号；名称失焦调重名检查，命中显示「已存在同名供应商」但不阻断保存；字段 = 名称、联系方式、期初应付、备注；期初应付提示「系统上线前已发生的净应付；上线后的付款照常登记采购付款」；PC 用 PageFrame，保存 / 取消与错误提示放固定操作区。
- **详情页**：与客户详情同构——横排信息条（编号、名称、状态、创建日期、期初应付（为 0 不显示）、累计采购、累计付款、应付）+ 联系信息 / 备注长文本卡；只读展示 + 编辑入口，操作区 = 编辑 / 返回列表，不提供详情删除；累计三项引用 finance 应付批量接口，接口失败显示 `0.00`，不阻断页面。
- **移动页（`/m/purchase/suppliers` 等）**：列表、新建、详情、编辑四个路由；列表用移动列表骨架（搜索按名称、卡片、加载更多、空态），卡片显示名称 + 应付 + 状态；详情固定标题「供应商详情」，名称右侧状态标签，信息条展示期初应付（非 0 时）/ 累计采购 / 累计付款 / 应付（负数显示「（预付）」），分隔线后为联系信息 / 备注 / 创建日期；`supplier:manage` 可停用（二次确认）/ 启用（直接生效）/ 删除（确认前查采购单数量），删除为描边 + 图标按钮，操作失败在按钮下方提示；加载 / 失败用移动列表态组件；底部固定条只放编辑 / 返回列表；表单含期初应付，控件高 48px；移动端不展示编号、不做批量；权限 `supplier:view` / `supplier:manage`。

### 删除规则

- 删除为软删除，仅用于误建、重复与测试数据清理；有采购单的供应商也可删除，历史采购单靠名称快照保留，编号不回收；删除需二次确认，文案含该供应商的采购单数量（取自采购单汇总接口），并说明历史保留与编号不回收。

### 与其他领域的边界

- **finance**：应付（累计采购 / 累计付款 / 应付）归 finance，经 `GET /api/v1/finance/payables` 批量引用；供应商不建金额冗余列，唯一例外是期初应付。付款挂供应商的名称快照由 finance 经 `SupplierService.findById` 取得。
- **purchase**：采购单保存时经 `assertSelectable(id)` 校验供应商存在且启用；采购单保留供应商名称快照，供应商后续改名不影响历史单据。
