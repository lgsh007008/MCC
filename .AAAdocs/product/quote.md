# 报价领域（quote）

> 定位：报价领域的**需求**（What）。实现设计见 `design/quote.md`（待建）。
> 编号规则：`R-报价-NNN`。本文件当前为该领域首个需求落地前的**产品讨论稿**，用户故事暂用 `US-N` 编号，进入需求流转时再分配正式编号。
> 对外产品名：**在线包装方案平台**（内部领域名仍为 `quote`）。

---

## 一、定位与目标

**一句话定位**：客户输入装什么、多重、多大、去哪，平台实时输出价格 + 结构图 + 料单，确认即下单——木包装行业的嘉立创。

**终极目标**：让木包装采购从微信询价、等老师傅、改一次重来一轮，变成全程自助、分钟级出方案、下单即锁定。

**一期目标（验证阶段）**，验证三个假设：

1. 客户愿意自助出方案，不等人工
2. 引擎产出的价格在真实成交中站得住脚
3. 方案形态（价 + 图 + 料单）比裸价格更能促单

---

## 二、目标用户与画像

| 用户 | 画像 | 特征 | 核心诉求 |
| --- | --- | --- | --- |
| 设备厂老板/采购（老王型） | 40~55 岁，中小制造企业，习惯微信询价 | 不懂木箱参数，没耐心填表 | 快、省心、别让我研究 |
| 外贸公司跟单（小刘型） | 25~35 岁，懂一点包装，服务海外买家 | 需要拿方案给客户确认 | 合规（熏蒸/IPPC）、有图、交期可查 |
| 仓库/车间主管（老李型） | 负责发货，箱型相对固定 | 高频复购 | 一键复用、下单快、状态透明 |

三类人共同点：木箱是采购链路里最不起眼、却又最磨人的一环——金额不大但耽误发货，没人愿意为等报价耗一天。

## 三、客户痛点矩阵

| 阶段 | 现状痛点 | 客户的隐性成本 | 平台解法 |
| --- | --- | --- | --- |
| 找供应商 | 靠熟人介绍，一家家问 | 比价范围窄，不知道市场价 | 网页即用，先自助试算再决定联系谁 |
| 询价 | 微信发规格，等半天到一天 | 项目排期被动 | 秒级自助出价 |
| 改规格 | 改一次尺寸，全部报价作废重来 | 一个项目改 3~5 版是常态 | 页面拖动参数，实时重算 |
| 选配置 | 不懂行，板材厚度、底梁根数全靠对方说 | 怕被宰、怕不够用 | 系统按承重自动配结构，客户语言替代技术名词 |
| 比价 | 各家报价格式不一，有的只报总价 | 无法横向对比 | 标准方案页：价 + 图 + 料单，三家可比 |
| 下单 | 讨价还价、细节确认全靠聊天记录 | 信息丢失、出错无据 | 方案确认即下单，全程留痕 |
| 履约 | 交期随口承诺，延误没人负责 | 发货计划被打乱 | 在线锁定交期，状态可查 |
| 收货 | 货不对板没依据 | 纠纷成本 | 方案图即合同附件 |
| 小单 | 批量小，厂家爱答不理、报价虚高 | 长尾需求无人服务 | 自助模式服务成本趋零，小单同样被认真对待 |

**一句话归纳**：客户最大的痛点不是贵，是询价环节的**信息黑洞**——问得慢、改得烦、看不懂、比不了、怕被坑。平台的价值主张是换成：**快、可改、看得懂、可对比、可追责**。

## 四、用户故事（按客户任务推进）

> 传统模式「先问价、后出图」是两件事；本平台报价即出图，价格、结构图、料单是同一参数算出的三样产物，天然一体，故合并为「自助出方案」单阶段。

### （一）自助出方案（从进站到拿到完整方案）

| 编号 | 用户故事 | 验收标准 |
| --- | --- | --- |
| US-1 | 作为首次来访的客户，我想不注册、不等待，输入需求就拿到完整方案，判断值不值得继续 | 未登录可用；合法参数秒级出结果 |
| US-2 | 作为不懂参数的客户，我想用大白话描述需求（有台两吨机床要出口德国），系统替我配好 | 对话抽取的参数完整回填表单，客户可见可改；理解不清时反问而非硬猜 |
| US-3 | 作为专业采购，我想精确调整板材厚度、底梁根数等参数做配置对比 | 高级参数面板暴露所有可调项；调整即重算 |
| US-4 | 作为客户，我想边看边改——改任何参数，价格、结构图、料单一起实时刷新 | 参数变更后方案三要素同步刷新，无需重新提交 |
| US-5 | 作为客户，我想方案一次给全：价格、结构图、3D 预览、料单明细 | 方案页四项齐备；同参数任何时间输出一致 |
| US-6 | 作为出口业务客户，我想系统自动提示熏蒸与标识要求 | 选出口目的国后自动给出熏蒸/IPPC 要求及对应加价项 |

### （二）确认与下单（从认可方案到订单锁定）

| 编号 | 用户故事 | 验收标准 |
| --- | --- | --- |
| US-7 | 作为客户，我想确认方案后直接在线下单并锁定交期 | 方案一键转订单；交期写入订单，全程留痕 |

### （三）履约与复购（从下单到下次再来）

| 编号 | 用户故事 | 验收标准 |
| --- | --- | --- |
| US-8 | 作为客户，我想随时查订单状态，按交期安排发货计划 | 状态实时可查，交期承诺留痕可追责 |
| US-9 | 作为复购客户，我想一键复用上次规格再下一单 | 历史方案可一键载入，改参数即新方案 |

## 五、端到端流程

### 客户主线（对客侧）

```
进入平台
 ├─ 入口 A：向导式表单
 │    第一层只问四件事：装什么 / 多重 / 多大 / 去哪
 │    专业参数收进高级选项
 │
 └─ 入口 B：对话式询价
      规则式问答引导为主（结构化、零幻觉）
      客户说绕了交 LLM 兜底理解
      每次理解显性化：我理解您是…… 客户确认后才入引擎
        ↓
 参数归一化：两个入口写入同一份参数状态
        ↓
 报价引擎（纯函数）：价格 + 结构图 + 料单，秒级输出
   —— 边看边改是出方案的自然部分：
      改参数即时三要素同刷；出口合规问答也在方案页内完成
        ↓
 确认下单：新客留联系方式；锁定交期
        ↓
 履约跟踪：状态可查，交期留痕
        ↓
 收货 → 一键复购（规格库）
```

### 厂内主线（内部承接）

```
订单进入订单模块
 → 方案自带的下料清单直接进生产（套裁领料）
 → 加工报工
 → 发货，状态回写
```

两段之间的桥是**同一份方案参数**：对客方案物即厂内生产指令——传统模式里报价和下单两拨人两头传话所没有的贯通性。

### 异常分支

| 场景 | 处理 |
| --- | --- |
| 尺寸超出产能（超大/超重） | 方案页明确提示并转人工，不出假价 |
| 对话无法理解需求 | 反问澄清，最多三轮；仍不清则转人工 |
| 异形件（贴设备形状） | 出示意草图 + 转人工深化，不承诺自动出正式图 |
| 板材行情波动 | 引擎参数走配置表，行情变更新参数，公式不动 |

## 六、报价模型骨架（参数待标定，不填任何数字）

### 输入变量（客户语言）

装什么（货物类型）、多重（毛重 G）、多大（内尺寸 L/W/H）、去哪（国内/出口目的地）、数量 N、附件需求（托盘/内衬/缓冲）

### 客户语言 → 工程参数翻译表（双入口的关键中间层）

| 客户语言 | 工程参数 |
| --- | --- |
| 装什么（易碎/精密/普通） | 缓冲等级、内衬配置 |
| 多重 | 底梁截面、根数、档距 |
| 去哪（国内/出口国） | 材质、是否熏蒸、IPPC 标识 |
| 多大 | 箱体展开面积、板材用量 |

### 算料公式（符号化）

```
展开面积 A = 2×(L×W + L×H + W×H)
板材用量   = A ÷ η            η = 套裁利用率，待实测
底梁根数   = ⌈G ÷ 单梁承重⌉ 与 ⌈L ÷ 标准间距⌉ 取大
梁料体积   = Σ(根数 × 截面 × 长度)
钢带用量   = 箱体周长 × 道数
```

### 计价合成

```
材料成本 = 板材量×单价 + 梁料×单价 + 钢带×单价 + 辅料定额 + 熏蒸费
报价     = (材料成本 + 加工成本 + 运费) × (1 + 管理费率) × (1 + 利润率)
```

### 待标定参数（真值来源，逐项询价实测）

板材单价（问自家锯材厂）、套裁利用率 η（老师傅试算）、单箱工时与人工费（现场实测）、钢带五金定额（询供应商）、熏蒸单价（询当地机构）、管理费率与利润率（经营决策）。

### 关键设计判断

1. 公式是规则写进引擎，η、人工费是参数放配置表——改价不碰代码
2. 对外报价可归一为「展开面积 × 综合系数」或「方数 × 综合单价」，竞对无法从报价反推成本结构
3. 引擎输出物定义为**报价方案物**：价格 + 结构参数 + 图纸数据，图纸渲染与报价展示消费同一份数据——报价即出图由此成立

## 七、AI 增量边界

**红线**：大模型绝不碰价格。报价必须确定、可复现、可解释，算价归规则引擎，这是架构底线。

**真实增量（没有 AI 就不成立的部分）**：

| 增量点 | 没有 AI 的状态 | 定性 |
| --- | --- | --- |
| 自然语言 → 参数翻译 | 不熟表单的客户无法自助 | 接住非专业客户，扩大自助覆盖面 |
| 出口合规问答（RAG） | 靠客服人力，下班就断 | 7×24，边际成本趋零 |
| 方案解释 | 客户看不懂为什么配 6 根梁 | 信任建设，促进成交 |
| 照片估尺 | 完全无此能力 | 精度风险大，二期评估 |

**伪增量排除**：LLM 算价（是风险）、寒暄闲聊（浪费 token 不产生转化）。判断标准：**AI 的每一步输出，要么把到不了引擎的人送进引擎，要么把人工回答变成自动回答，其余都是装饰。**

**降级方案**：LLM 不可用时，对话入口回退到纯规则式问答引导，保证对话入口始终可用。

## 八、需求真实性验证计划

**唯一标尺**：客户现在是否正在为这个问题持续付费（钱或时间）。等报价的时间就是客户在持续支付的成本。

**五步验证（按成本从低到高）**：

1. **访谈实证**：找 10 个真实询价客户（设备厂采购、外贸跟单各半），不推销只观察：你现在怎么询价？最近一次从发规格到拿到价用了多久？改了几版？信号看抱怨的频次和细节
2. **假门测试**：静态落地页放自助算价按钮，点击后引导人工表单或微信。统计愿意自助填写的访客比例——需求的硬数据
3. **重复询价实验**：同一规格隔两周问同一供应商两次，记录报价差。差异大 = 价格不透明痛点实证成立
4. **引擎灰帽试点**：人工接单照旧，但报价数字改用引擎计算，观察成交率是否持平——先验证引擎，再验证前端
5. **老客户闭环试点**：让 2~3 家已有关系客户改用网页自助，看是否真的不再找人工

**证伪条件（提前写死，出现任一即承认假设不成立）**：

- 自助入口有流量但提交率长期极低
- 试点客户明确表示还是想找人聊，不认页面方案
- 引擎报价与人工报价的成交率明显倒挂

MVP 要验证的核心假设只有一句：**客户是否愿意自助。**

## 九、对标嘉立创：优化与提升点

**先承认差距**：嘉立创赢在自建产能、供应链议价、电子客户天然线上化。木包装客户线上化程度低是真实劣势，获客教育成本高。

**我们的优化空间，恰好藏在本行业差异里**：

| 维度 | 嘉立创 | 我们的优化点 |
| --- | --- | --- |
| 客户专业度 | 客户是工程师，看得懂 Gerber | 客户不懂行 → 可视化做到傻瓜级（3D 把设备放进箱子里看） |
| 询价入口 | 只有表单（当年无 LLM） | 双入口 + 对话翻译，AI 是嘉立创模式确立时没有的时代红利 |
| 方案形态 | 报价 + 确认文件，客户被动确认 | 改配置实时重算 + AI 解释依据，交互深度更强 |
| 履约透明 | 状态点式进度 | 交付链只有几天，做小时级状态 + 生产拍照回传 |
| 复购设计 | 历史订单可查 | 客户规格库 + 一键复购 + 年度降本台账，复购变成被服务感 |
| 生态纵深 | PCB → 商城 → SMT | 木箱 → 熏蒸、托盘、内衬、现场打包，包装整体方案更贴小客户 |

一句话结论：嘉立创赢在客户本来就在网上；我们要赢的点是**客户本来不在网上，所以用 AI 和傻瓜级可视化把他请上来，再用本地化产能接住他**——这恰好是嘉立创当年想做而技术上做不了的。

## 十、MVP 范围与分期

| 期 | 内容 |
| --- | --- |
| P0 | 向导式表单入口 + 规则引擎报价 + 方案页（价 + 结构图 + 料单，边看边改） |
| P0.5 | 对话入口第一版（规则式问答引导为主，LLM 兜底理解） |
| P1 | 在线下单 + 履约跟踪 + 交期锁定 |
| P2 | LLM 对话增强、照片估尺、客户规格库与一键复购 |

双入口同在 MVP 范围内（已拍板），对话入口第一版以规则式问答保底，LLM 作兜底增强——确定性优先。

## 十一、验收口径（定性，不编数字）

- 客户从进站到拿到完整方案，分钟级完成
- 同参数任何时间、任何人询价，结果完全一致
- 方案页价 + 图 + 料单齐备，可直接作为下单依据
- 对话入口理解的参数全部显性回填表单，客户可见可改
- 超产能与异形件场景明确转人工，不出假价
