# 客户领域（customer）

> 定位：客户领域的**需求**（What）。实现设计见 `design/customer.md`。
> 编号规则：`R-客户-NNN`
> 范围界定：客户档案的建立、查询、编辑、启用与停用，以及累计下单方量、累计销售、累计收款与欠款的展示口径。应收口径归 finance 域（`R-财务-002`），本域只引用展示，不重复定义。

---

## R-客户-001：客户档案

调研依据：飞书「客户」表（客户编号 / 客户名称 / 联系信息 / 备注 / 创建日期）；销售侧的客户使用现状见 `product/order.md` 与 `.战略与经营/01第一阶段规划/业务现状与需求调研.md`。

### 字段口径

| 字段 | 口径 |
| --- | --- |
| 客户编号 | 系统自动生成（CT + 5 位流水，如 CT-00001；不含日期），只读、永不复用 |
| 客户名称 | 手填，必填；不做唯一约束，重名时提示但不阻断保存 |
| 联系信息 | 文本，选填（电话等，多值可分行填写） |
| 期初欠款 | 手填，选填；系统上线前已发生的净欠款，≥ 0、两位小数、默认 0；只作欠款基数，不计入累计销售与经营收支 |
| 备注 | 手填，选填 |
| 状态 | 枚举：启用 / 停用；新建默认启用 |
| 创建日期 | 系统写入（记录创建时间），只读 |
| 累计下单方量 | 只读，= 该客户名下未软删销售单的合计方量之和；4 位小数，无单据显示 0.0000 |
| 累计销售 | 只读，= 该客户名下未软删销售单的合计金额之和；2 位小数 |
| 累计收款 | 只读，= 该客户名下未软删销售回款流水的合计金额；2 位小数 |
| 欠款 | 只读，= 期初欠款 + 累计销售 − 累计收款；负数显示为「预收」，不截断 |

### 编号规则

- 格式 `CT` + 连字符 + 5 位全局流水（如 `CT-00001`），流水在租户内全局递增、超出 5 位自然进位
- 系统生成、只读、永不复用；停用或软删后编号不回收
- 全局格式见 `1-产品文档.md`「五、全局编号规范」；本域只登记前缀 `CT`，不再单独定义格式

### 重名规则

- 客户名称**不建唯一约束**：现实中可能存在同名客户，强行唯一会让无法建档
- 保存时若存在同名（同租户、未软删）客户，界面提示「已存在同名客户」；用户确认后仍可保存
- 不做客户合并：别名与同名归并在存量回填时人工确认，本轮不建合并功能

### 状态规则

- 新建默认「启用」；启用与停用可双向切换
- **停用**用于客户流失或暂停合作：档案与历史单据全部保留，只是不可被新销售单选择
- **停用后不可被新销售单选择**；编辑历史单据且客户未变更时仍可正常保存（否则历史单会变成无法保存的死单）

### 删除规则

- **软删除**：删除仅把档案从列表与下拉中移除（`deleted_at` 落值），不做物理删除；编号不回收、不再复用
- **允许删除有销售单的客户**：历史销售单保留，继续显示下单时的客户名称快照；订单详情中的客户编号标注「已删除」
- **删除后**：不可再被新销售单选择；编辑历史单据时该客户仍保留在单据上（可照常保存其余字段）
- **不可恢复**：UI 不提供恢复入口；需要保留客户时请用停用，删除只用于误建、重复与测试数据清理
- 删除为不可恢复动作，按 `product/平台布局.md` 二次确认规范确认，文案须写明该客户的销售单数量与「历史单据保留」

| 动作 | 档案可见 | 可开新单 | 历史单据 | 可恢复 |
| --- | --- | --- | --- | --- |
| 停用 | 可见（标停用） | 否 | 保留 | 可重新启用 |
| 删除 | 不可见 | 否 | 保留（名称快照） | 否 |

### 累计下单方量

- 口径：该客户名下、**未软删**销售单的合计方量之和
- **所有明细行均计方量**：含按根数计价的行，方量统一按长度 × 宽度 × 高度 × 根数计算并落库；无销售单时显示 0.0000
- 时间范围：全部历史，不设区间筛选
- 精度：4 位小数（与销售单方量口径一致）
- 数据来源：order 域的客户方量汇总接口（定义在 `design/order.md` 接口清单，本领域只引用不重述）
- 排序：支持按累计方量对**筛选后全量**排序，首次点击默认降序；客户数超过 500 时该列不可排序并给出提示（取数与分页策略见 `design/customer.md`）

### 应收展示（引用 finance 口径）

- 累计销售 = 未软删销售单合计（现结单取实收金额、赊销单取合计金额）；只统计系统内的销售单
- 累计收款 = 挂该客户的销售回款流水合计；只统计系统内的流水
- 期初欠款 = 系统上线前已发生的**净欠款**，客户档案手填（≥ 0，两位小数，默认 0）；历史回款不补录
- 欠款 = 期初欠款 + 累计销售 − 累计收款；负数为预收，显示为「金额（预收）」
- 期初欠款不进入累计销售、不计入经营收支，只作欠款基数
- 不做账龄、不做单笔核销；收款按客户总欠款冲减（口径归 `R-财务-002`）
- 数据来源：finance 的批量应收接口（定义在 `design/finance.md` 接口清单，本领域只引用不重述）
- 已知取舍：历史为**预收**（客户多付）的客户暂无法表达，期初欠款按 0 处理，如确有需要另议

### 页面设计

按 `product/平台布局.md` 页面模式规范执行，本页特有口径如下：

- **列表页**：筛选字段 = 客户名称（模糊）、状态；列 = 编号、客户名称、联系信息、状态、累计下单方量、欠款、备注、创建日期；排序列 = 创建日期（默认倒序）、累计下单方量（首次点击降序，对筛选后全量生效）；行操作 = 查看 / 编辑 / 停用（启用）/ 删除；批量操作 = 新建 + 选中后批量启用 / 批量停用 / 批量删除（混合选择按目标状态幂等处理：已处于目标状态的跳过，无任何将变更时对应按钮禁用；确认文案给出将变更与跳过条数）；无数值汇总意义，省略合计行；单条停用、删除与全部批量动作按 `product/平台布局.md` 二次确认规范确认，单条启用直接执行
- **表单页**：标题 = 新建客户 / 编辑客户 + 客户编号；标题区与底部保存 / 取消固定，中间内容独立滚动；字段 = 客户编号、客户名称、联系信息、期初欠款、备注；客户编号只读，新建时显示占位「系统生成」，编辑时显示真实编号；期初欠款为金额输入（≥ 0、两位小数、默认 0），字段下方提示「系统上线前已发生的净欠款；上线后的回款照常登记销售回款」；状态不在表单内编辑（经列表行操作切换）；校验：客户名称必填；重名提示显示在名称字段下方，不阻断提交
- **详情页**：标题 = 客户名称（客户编号括注），标题区与底部编辑 / 返回列表固定，信息条与主体随内容区滚动；信息条 = 客户编号、状态、期初欠款（为 0 时不显示）、累计下单方量、累计销售、累计收款、欠款、创建日期；主体 = 联系信息、备注；**不嵌该客户的销售单列表**（见待补注记）
- **移动页（移动 Web，`/m`，适老化）**：按 `product/平台布局.md`「移动页」模式执行，入口 = `/m` 首页「客户档案」卡片；本页特有口径如下：
  - **列表**：整行搜索框（客户名称模糊，回车即查，查询后回第 1 页）+ 卡片列表（主行 = 客户名称大字，次行 = 联系信息，状态用启用 / 停用小标签）+「加载更多」；不展示客户编号；不设筛选组、多选与批量操作；`customer:manage` 时底部固定「新建客户」主按钮（与销售单一致）
  - **详情**：标题 = 客户名称；信息条 = 状态、期初欠款（为 0 时不显示）、**累计下单方量、累计销售、累计收款、欠款**、联系信息、备注、创建日期（**不展示客户编号**）；累计四项口径同 PC（欠款为负显示「金额（预收）」，正数用警示色）；`customer:manage` 提供「停用 / 启用」（停用二次确认，启用直接执行）与「删除」；底部固定「编辑」「返回列表」
  - **表单（新建 / 编辑）**：独立移动页，单列、Label 在上；字段 = 客户名称、联系信息、期初欠款、备注；保存吸底；校验与重名提示同 PC（重名只提示不阻断提交）
  - **删除**：二次确认前查询该客户销售单数量，文案含「该客户有 N 张销售单；删除后历史单据保留名称快照，不可恢复」；删除后回列表
  - **权限**：查看 `customer:view`；新建 / 编辑 / 启停用 / 删除 `customer:manage`
  - **移动端不做**：批量启停用、批量删除、按累计方量排序、联系信息自动拨号

### 待补与归属注记

- **累计收款金额、欠款余额**：已由 finance 域 `R-财务-002` 落地，客户列表与详情引用展示（见「应收展示」）
- **客户详情页的销售单列表**：本轮不做。若后续需要，按跨模块页面规则在 customer 页面内引用 order 的列表接口，不新建聚合模块、不读 order 的表
- **客户合并（同名 / 别名归并）**：本轮不做，存量回填时人工确认
- **删除与财务的联动**：本轮仍允许删除有欠款的客户，不做阻断（欠款为只读派生值，客户删除后历史销售单与收款流水的 customerId 仍保留）；如需强制结清后再删，另立需求
