> 定位：本文件定义审计日志领域的**需求**（What / Why）。实现设计见 `design/审计日志.md`。
> 编号规则：`R-审计-NNN`

## R-审计-001：操作审计

**定位**：供管理员追溯所有账号（含管理员）关键操作的业务审计记录；不是服务器运行日志，也不是业务台账。技术日志（pino）只用于排障，不承担本需求。

**记录范围**：

- 所有写操作：新建、编辑、删除、启停用、改角色、重置密码、批量操作等；
- 身份操作：登录、登出、修改密码；
- 输出操作：打印、导出；当前覆盖销售单打印、包装方案报告打印与包装设计导出（SVG / DXF / CSV / OBJ / STL）；未来新增输出按同一口径接入；
- 失败操作同样记录（如校验失败、权限不足、删除失败）；
- **不记录**普通列表查看、详情查看、刷新令牌等自动请求；
- **不排除管理员**：管理员的操作与普通账号一样进入审计列表。

**记录内容**：

| 字段 | 口径 |
| --- | --- |
| 时间 | 操作发生时间，按系统时区展示 |
| 操作人 | 账号名快照 + 账号 ID；登录失败时账号 ID 为空、账号名为尝试登录的账号 |
| 角色 | 操作发生时的角色快照；后续改角色不回写历史 |
| 动作 | 中文动作名，如「新建销售单」「删除客户」「打印销售单」 |
| 领域 / 动作标识 | 机器可读的领域与动作，如 `order / update`，供筛选与兼容旧数据 |
| 对象 | 对象类型、对象 ID、对象编号（如销售单 SO-00001、客户 CT-00001）；批量操作记录条数 |
| 结果 | 成功 / 失败；失败同时记录 HTTP 状态与错误码（如有） |
| 终端 | IP、User-Agent |
| 关联标识 | requestId，用于与技术日志关联 |

**不记录敏感内容**：请求体全文、密码、访问令牌、刷新令牌、文件内容不得进入审计记录。

### 页面设计

按 `product/平台布局.md` 列表页模式执行：

- 入口：顶栏头像下拉「审计日志」，仅管理员可见；不占侧边业务分组；
- 路由：`/admin/audit-logs`；
- 筛选：时间范围（默认最近 30 天）、操作人（模糊）、领域、动作、结果；
- 列：时间、操作人、角色、动作、对象、结果、IP；
- 分页：默认每页 20 条，按时间倒序；无多选、无批量操作、无删除、无导出；
- 只读：页面不提供任何修改或删除入口；无权限直接访问显示统一无权限提示。

### 权限与留存

- 新增 `audit:view`，仅管理员角色拥有；不设 `audit:manage`，审计只读；
- 其他角色看不到入口，服务端返回 403；
- 审计日志只增不删，当前不设自动清理；未来归档或清理策略另立需求。平台运营跨租户操作另见 R-审计-002（独立表与页面）。

### 边界

- 审计为**最佳努力记录**：写入失败不阻塞业务，可能因进程异常丢失少量记录；不保证与业务事务强一致，不作为财务级不可抵赖凭证；
- 旧记录若缺少中文动作名或对象编号，页面以 `领域 / 动作` 等原始字段兜底，不伪造历史数据；
- 打印与导出均为前端行为，记录的是「用户触发了打印 / 导出」，不保证打印机实际出纸或文件实际保存 / 外发；未保存工作台没有方案编号的导出不记录。

### 验收标准

1. 管理员可查询本人和其他账号的写操作、登录/登出/改密、打印与导出记录；
2. 销售、财务、工人访问审计页被拒绝（前端无入口，服务端 403）；
3. 写操作成功与失败均有记录，失败记录包含状态码；
4. 审计记录中不存在密码、令牌或请求体全文；
5. 筛选、分页、时间倒序正常；
6. 管理员操作不被排除；
7. 包装设计报告打印与导出产生审计记录，含方案编号；导出格式与版本记录在审计 payload（列表页暂不展示）；未保存工作台无方案编号的导出不记录。

## R-审计-002：平台运营跨租户操作审计

**定位**：记录平台运营账号对租户、套餐、平台账号的关键操作，供追责与排障；与租户内审计（R-审计-001）分表、分页面，互不混杂。

**记录范围**：

- 租户：开通、编辑、停用 / 启用、改套餐、功能开关、重置租户管理员密码；
- 套餐：新建、编辑、停用 / 启用；
- 平台运营账号：新建、重置密码、停用 / 启用、登录成功 / 登录失败 / 登出 / 改密；
- 失败操作同样记录（校验失败、权限不足、目标不存在）；
- **不记录**平台运营的普通列表与详情查看。

**记录内容**：

| 字段 | 口径 |
| --- | --- |
| 时间 | 操作发生时间，按系统时区展示 |
| 操作人 | 平台账号名快照 + 账号 ID；登录失败时账号 ID 为空、账号名为尝试登录的账号 |
| 动作 | 中文动作名，如「开通租户」「停用租户」「修改套餐」「重置租户管理员密码」 |
| 动作标识 | 机器可读的领域与动作，如 `tenant / suspend` |
| 目标租户 | 目标租户编号 + 名称快照；平台账号自身操作无目标租户时为空 |
| 结果 | 成功 / 失败；失败记录 HTTP 状态与错误码（如有） |
| 终端 | IP、User-Agent |
| 关联标识 | requestId，用于与技术日志关联 |

- 不记录请求体全文、密码、令牌、租户业务数据内容。

**页面设计**：

- 入口：`/ops/audit-logs`，平台运营菜单；
- 筛选：时间范围（默认最近 30 天）、操作人（模糊）、动作、目标租户、结果；
- 列 = 时间、操作人、动作、目标租户、结果、IP；
- 按时间倒序；分页默认 20；无多选、无批量、无删除、无导出；
- 只读；无权限直接访问显示统一无权限提示。

**权限与留存**：

- `platform:audit:view`，当前仅 `PLATFORM_ADMIN` 拥有；不设 manage；
- 独立表，只增不删；不设自动清理；未来归档策略另立需求。

**边界**：

- 最佳努力记录：写入失败不阻塞业务，可能因进程异常丢失少量记录；
- 不保证与业务事务强一致，不作为财务级不可抵赖凭证；
- 打印 / 导出类操作仍归租户审计（R-审计-001），不进入平台审计。
