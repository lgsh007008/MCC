## R-审计-001：操作审计

**定位**：供管理员追溯所有账号（含管理员）关键操作的业务审计记录；不是服务器运行日志，也不是业务台账。技术日志（pino）只用于排障，不承担本需求。

**记录范围**：

- 所有写操作：新建、编辑、删除、启停用、改角色、重置密码、批量操作等；
- 身份操作：登录、登出、修改密码；
- 输出操作：打印、导出；当前 MCC 实际只有销售单打印，未来新增导出按同一口径接入；
- 失败操作同样记录（如校验失败、权限不足、删除失败）；
- **不记录**普通列表查看、详情查看、刷新令牌等自动请求；
- **不排除管理员**：管理员的操作与普通账号一样进入审计列表。

**记录内容**：

| 字段 | 口径 |
| --- | --- |
| 时间 | 操作发生时间，按系统时区展示 |
| 操作人 | 账号名快照 + 账号 ID；登录失败时账号 ID 为空、账号名为尝试登录的账号 |
| 角色 | 操作发生时的角色快照；后续改角色不回写历史 |
| 动作 | 中文动作名，如「新建销售单」「删除客户」「打印销售单」 |
| 领域 / 动作标识 | 机器可读的领域与动作，如 `order / update`，供筛选与兼容旧数据 |
| 对象 | 对象类型、对象 ID、对象编号（如销售单 SO-00001、客户 CT-00001）；批量操作记录条数 |
| 结果 | 成功 / 失败；失败同时记录 HTTP 状态与错误码（如有） |
| 终端 | IP、User-Agent |
| 关联标识 | requestId，用于与技术日志关联 |

**不记录敏感内容**：请求体全文、密码、访问令牌、刷新令牌、文件内容不得进入审计记录。

### 页面设计

按 `product/平台布局.md` 列表页模式执行：

- 入口：顶栏头像下拉「审计日志」，仅管理员可见；不占侧边业务分组；
- 路由：`/admin/audit-logs`；
- 筛选：时间范围（默认最近 30 天）、操作人（模糊）、领域、动作、结果；
- 列：时间、操作人、角色、动作、对象、结果、IP；
- 分页：默认每页 20 条，按时间倒序；无多选、无批量操作、无删除、无导出；
- 只读：页面不提供任何修改或删除入口；无权限直接访问显示统一无权限提示。

### 权限与留存

- 新增 `audit:view`，仅管理员角色拥有；不设 `audit:manage`，审计只读；
- 其他角色看不到入口，服务端返回 403；
- 审计日志只增不删，当前不设自动清理；未来归档或清理策略另立需求。

### 边界

- 审计为**最佳努力记录**：写入失败不阻塞业务，可能因进程异常丢失少量记录；不保证与业务事务强一致，不作为财务级不可抵赖凭证；
- 旧记录若缺少中文动作名或对象编号，页面以 `领域 / 动作` 等原始字段兜底，不伪造历史数据；
- 打印是前端行为，记录的是「用户触发了打印」，不保证打印机实际出纸。

### 验收标准

1. 管理员可查询本人和其他账号的写操作、登录/登出/改密、打印记录；
2. 销售、财务、工人访问审计页被拒绝（前端无入口，服务端 403）；
3. 写操作成功与失败均有记录，失败记录包含状态码；
4. 审计记录中不存在密码、令牌或请求体全文；
5. 筛选、分页、时间倒序正常；
6. 管理员操作不被排除。
