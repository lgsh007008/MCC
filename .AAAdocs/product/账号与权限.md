# 账号与权限领域（auth）

> 定位：账号与权限领域的**需求**（What）。实现设计见 `design/账号与权限.md`。
> 编号规则：`R-账号与权限-NNN`
> 范围界定：账号、角色、权限、登录会话、令牌与鉴权守卫，以及平台运营账号；区分租户用户与平台运营两个身份平面。登录页与平台运营登录页归属本领域（页面归属唯一）；实现规范（技术口径）见技术方案 §8，本文件只定需求口径。

---

## R-账号与权限-001：登录、账号与权限

**登录方式**：租户编号 + 账号 + 密码；服务端先校验租户存在且启用，再在该租户内校验账号密码；登录成功进入平台首页（首页随首个业务领域需求创建后登记入 `product/平台布局.md` 菜单表）；支持「记住登录」（勾选后刷新令牌长期有效，时长见 `design/账号与权限.md` §4：不勾选会话级）。平台运营账号使用独立入口 `/ops/login`，见 R-004，不走本登录页。租户不存在、租户停用与账号密码错误统一返回同一提示，不区分原因。

**登录标识的现状与演进**：当前为单租户形态（租户「梅好木业」，编号 `TN-00001`），登录页预填 `TN-00001`，使用者只需输入账号与密码。该预填是当前正式策略，不是临时措施，线上同样只有一个租户，上线后照此执行。未来若升级为国内主流的「手机号 + 密码（或验证码）」登录，以手机号跨租户反查租户，登录页只保留手机号与密码两字段；触发条件为以下任一情况出现：出现第 2 个租户、对外开放注册或获客、需要短信找回密码。升级前须先具备手机号全局唯一（跨租户）、服务端租户解析入口与短信通道企业资质；在此之前保持租户编号登录不变。

**账号规则**：账号按使用人一人一号，账号在租户内唯一（不同租户可有同名账号），角色见 R-003；无自助注册，无外网开放注册入口；账号由管理员在「账号管理」页维护（R-002，1~2 个起步）

**当前初始化账号**：`admin`（属于租户 `TN-00001`），初始密码 `Mcc@2026`（仅内部初始化使用，首次登录后请及时修改；与 `apps/server/scripts/seed.ts` 保持一致，账号密码变动时此处同步更新）；初始角色为管理员

**修改密码**：顶栏头像下拉进入

**登录失败保护**：按「租户编号 + 账号」维度计数，连续失败 5 次锁定 15 分钟（主流默认值，可调整）；平台运营登录独立计数，见 R-004

**登录页**：租户编号、账号、密码（输入框支持显示 / 隐藏切换）、登录按钮、记住登录；纯组件拼装，不单列页面设计

**角色与权限**：租户内角色清单、权限矩阵与 scope 口径见 R-003；平台运营角色与 scope 见 R-004，两个身份平面分离；权限校验统一在服务层守卫完成（见技术方案 §8.2），前端不做安全判断

## R-账号与权限-002：账号管理

**入口与权限**：仅管理员可进入；入口在顶栏头像下拉「账号管理」（平台机制页面，不占侧边业务分组）；直接访问无权限时显示无权限提示

**账号列表**：列 = 账号、角色、状态、创建日期；不显示密码；行操作 = 重置密码 / 改角色 / 停用（启用）；不做批量操作、不做物理删除

**页面设计**：按 `product/平台布局.md` 列表页模式执行——筛选区 = 账号（模糊）+ 查询；批量操作区 = 新建账号（左对齐）与角色权限说明（右端次级）；批量操作区显示「已用 X / 上限 Y」，额度取套餐、口径为未删除账号数（含停用），平台运营账号不计入；达到上限时新建账号按钮禁用并提示；表格无首列多选（本页无批量动作，按列表页模式例外处理）；分页 = 第 x / y 页 · 共 n 条；新建 / 重置密码 / 改角色弹窗最大宽约 520px；账面无数值汇总列，省略合计行

**角色权限说明**：账号管理页提供只读弹窗，展示四角色 × 订单 / 客户 / 采购 / 供应商 / 生产单据 / 库存 / 财务 / 材料毛利 / 账号管理 / 审计日志的权限矩阵；矩阵由代码中的角色权限映射生成，不手写；弹窗内说明 PC 与手机端共用同一套权限、手机端提供销售 / 客户 / 采购 / 供应商 / 生产与库存 / 资金页面，账号管理与审计日志仅 PC

**新建账号**：弹窗表单（按 `product/平台布局.md` 弹窗表单模式），字段 = 账号、初始密码、角色；账号租户内唯一；密码至少 8 位；保存前校验套餐额度，超限拒绝并提示；保存后关闭弹窗并刷新列表

**停用与启用**：停用后立即不可登录，并撤销该账号全部刷新令牌；启用后恢复登录；**不能停用自己**；**不能停用最后一个启用状态的管理员**

**重置密码**：管理员为该账号设置新密码，成功后撤销该账号全部刷新令牌（该账号需重新登录）；不提供邮件找回

**改角色**：管理员可在四个固定角色间切换；**不能把最后一个启用状态的管理员改为其他角色**；改角色后撤销该账号刷新令牌，访问令牌最多 15 分钟后自然失效

**边界**：不做账号删除、不做自助注册、不做密码找回、不做角色管理页（角色清单固定，见 R-003）

## R-账号与权限-003：角色与权限

**角色清单**（固定四个，不建角色表）：

| 角色 | 订单 | 客户 | 采购 | 供应商 | 财务 | 生产单据 | 库存 | 材料毛利 | 账号管理 | 审计日志 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 管理员 ADMIN | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 全部 | 查看 |
| 销售 SALES | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 查看 + 维护 | 无 | 无 |
| 财务 FINANCE | 查看 | 查看 | 查看 | 查看 | 查看 + 维护 | 查看 | 查看 | 查看 | 无 | 无 |
| 工人 WORKER | 仅查看 | 无 | 无 | 无 | 无 | 无 | 无 | 无 | 无 | 无 |

**权限单元**：页面级「查看 / 维护」两档，不做按钮级权限：

- `order:view`（销售单列表、详情、打印）/ `order:manage`（新建、编辑）
- `customer:view`（客户列表、详情）/ `customer:manage`（新建、编辑、启停用、删除）
- `purchase:view`（采购单列表、详情）/ `purchase:manage`（新建、编辑、删除）
- `supplier:view`（供应商列表、详情）/ `supplier:manage`（新建、编辑、启停用、删除）
- `finance:view`（资金流水、收支汇总）/ `finance:manage`（账户、流水的登记 / 编辑 / 删除）
- `production:view`（原木领用、方木产出列表 / 详情）/ `production:manage`（新建、编辑、删除）
- `inventory:view`（库存与估值、期初只读、盘点记录列表 / 详情）/ `inventory:manage`（期初设置、新建盘点）
- `profit:view`（销售单材料毛利）/ `profit:manage`（重算成本待补订单的材料成本）；重算后锁定
- 管理员、财务、销售三个角色对财务功能完全同等（查看 + 维护）；已知代价是销售可修改财务数据，当前接受该风险
- 管理员 / 销售对生产与库存查看 + 维护；财务只读；工人无；材料毛利管理员 / 销售查看 + 重算，财务查看
- 库存盘点菜单按 `inventory:view` 可见（财务可查记录）；「新建盘点」按 `inventory:manage` 显隐
- 销售单现结沿用 `order:manage`；采购单现结沿用 `purchase:manage`；收支汇总的两个页内 Tab 沿用 `finance:view`，不新增权限单元
- `account:manage`（账号管理）
- `audit:view`（审计日志列表）；只读，不设 `audit:manage`

拥有 `manage` 默认包含对应 `view`。页面内的新建 / 编辑 / 删除入口按是否拥有 `manage` 显隐。

**权限判定**：

- 服务端守卫按角色 → scope 判定，无权限返回 403；前端只做菜单与入口裁剪，不作为安全边界
- 同一套 scope 同时约束 PC 与移动 Web，不按端拆分权限；移动端列表 / 详情用 `view`，新建 / 编辑用 `manage`
- 菜单、头像菜单项与页面入口按 scope 裁剪；直接访问无权限页面显示无权限提示

**端与权限**：

- 租户用户一套账号、一套角色、一套 scope，PC 与移动 Web 只是两个界面；登录按视口宽度分流（宽屏 `/admin`、窄屏 `/m`）
- 平台运营账号是第二个身份平面：只进 `/ops`，不能进入 `/admin` 或 `/m`；租户账号不能进入 `/ops`；平台账号不计入租户账号数，不参与租户四角色矩阵
- 移动端提供销售单、客户、采购单、供应商、资金流水、收支汇总、原木领用、方木产出与库存页面：查看 / 维护按同一 scope 生效；材料毛利在销售单移动详情展示（成本待补时管理员 / 销售可重算）；账号管理、审计日志没有移动页面，属于产品范围而非独立权限
- 角色权限说明弹窗内展示上述关系；头像菜单显示当前账号与角色

**管理员规则**：管理员可以有多个；至少保留一个启用状态的管理员；不能停用自己；不能停用或降级最后一个启用管理员

**新增功能规则**：此后每个新增页面 / 功能必须声明权限单元（view / manage）与各角色的默认授权，并更新本矩阵；新增可售模块还须在 `product/租户.md` R-租户-003 登记 feature；声明规则见 `0-文档驱动开发机制.md`「新增功能的声明规则」；未声明 scope 的功能视为未完成

**边界**：当前为固定内置角色、不建角色表、不做角色管理页；未来需要租户自定义角色时另立需求，届时再评估角色表与迁移方案

## R-账号与权限-004：平台运营账号

**定位**：平台运营专用身份，只进 `/ops`，不属于任何租户，不计入租户账号数，不参与租户内四角色矩阵。

**入口与登录**：`/ops/login`，账号 + 密码；支持「记住登录」；登录成功进入 `/ops`，不按视口分流；与租户登录页互不通用；登录失败独立计数，连续失败 5 次锁定 15 分钟。

**当前初始化平台账号**：`opsadmin`（不属于任何租户），初始密码 `Mcc@2026`（仅内部初始化使用，首次登录后请及时修改；与 `apps/server/scripts/seed.ts` 保持一致，账号密码变动时此处同步更新）；初始角色为平台运营。

**账号字段**：

| 字段 | 口径 |
| --- | --- |
| 账号 | 全局唯一，手填，≤64 字 |
| 初始密码 | 开通时设置，至少 8 位；首次登录后建议修改 |
| 角色 | 当前仅 `PLATFORM_ADMIN`（平台运营）；不建平台角色表 |
| 状态 | 启用 / 停用 |
| 创建日期 | 系统写入，只读 |

**权限**：

- `platform:tenant:view`（租户列表、详情、套餐查看）、`platform:tenant:manage`（开通、编辑、启停、改套餐、功能开关、重置租户管理员密码）、`platform:account:manage`（平台运营账号管理）、`platform:audit:view`（平台审计）；
- 拥有 manage 默认包含对应 view，由共享 `scopeSatisfied` 统一判定；平台 scope 与租户 scope 是两套命名空间，互不授予。

**账号规则**：

- 一人一号；无自助注册；由现有平台管理员创建；
- 不能停用自己；不能停用或降级最后一个启用状态的平台管理员；
- 重置密码后撤销该账号全部刷新令牌；
- 停用后立即不可登录，并撤销全部刷新令牌；不做删除。

**跨租户账号操作**：

- 平台运营可在租户详情查看该租户 `ADMIN` 账号列表，并重置其密码；重置后撤销该账号刷新令牌；
- **不做代登录 / 模拟用户**；不展示租户其他角色账号，不修改租户账号的角色与状态。

**页面设计**：

- `/ops/accounts` 列表：筛选 = 账号（模糊）；列 = 账号、角色、状态、创建日期；行操作 = 重置密码 / 停用（启用）；无多选、无批量、无删除；分页默认 20；无数值汇总列，省略合计行；
- 新建账号弹窗（约 520px）：字段 = 账号、初始密码、角色；保存后关闭并刷新列表；
- 重置密码弹窗：字段 = 新密码、确认新密码；保存后撤销该账号刷新令牌。

**边界**：不做代登录、不做平台角色自定义、不做平台账号删除；平台账号不能访问 `/admin` 或 `/m`；租户账号不能访问 `/ops`。

**审计**：平台运营账号的新建、改角色、重置密码、停用、登录 / 登出 / 改密进入平台审计（`product/审计日志.md` R-审计-002）。
