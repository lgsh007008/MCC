## 1. 模块结构与职责

`modules/packaging` 为业务模块，遵循技术方案 §4.1 四件套模板：

```
modules/packaging/
├── packaging.controller.ts     # 方案 CRUD、复制、发布、版本、模板与材料目录
├── packaging.service.ts        # 编号、方案 / 单元 / 构件读写、合计重算、发布快照
├── dto/
│   └── packaging.dto.ts        # 方案 / 单元 / 构件 / 模板 / 材料 / 版本契约
├── packaging.module.ts         # exports: PackagingService
└── index.ts                    # 唯一公开出口
```

- `packaging_projects`、`packaging_units`、`packaging_parts`、`packaging_templates`、`packaging_materials`、`packaging_revisions` 归本模块。
- 几何、BOM 与校验纯函数沿用 `packages/shared/src/pallet.*`（P1 托盘构建器）；P2 起收敛到 `packages/shared/src/design/`，服务端与前端共用。
- 本模块**不导入** CustomerModule / OrderModule / ProductionModule；客户名称只作文本快照，不建外键、不生成销售单。
- 模板与材料目录 v1 只读；租户首次读取时按预置数据落库，后续由平台运营统一维护。
- 托盘单元保留现有 2D / 3D / 打印能力；木箱与后续单元复用同一几何与图纸管线。

## 2. 数据模型概览

> 细节归 `packages/db/prisma/schema.prisma`（表结构唯一事实源，技术方案 §5），此处只列概览与约定。

| 表 | 角色 | 字段要点 | 约束 |
| --- | --- | --- | --- |
| `packaging_projects` | 方案，商业与工程分组 | 编号 `PD-#####`、名称、客户名称快照、使用范围、状态、合计体积 / 重量 / 材料费 / 加工费、当前版本号、备注、软删除 | 唯一 `(tenant_id, code)`；索引 `(tenant_id, updated_at)`、`(tenant_id, status)` |

| `packaging_parts` | 构件 | 所属单元、行序、构件角色、名称、材料 code、方向、长 / 宽 / 厚（整数 mm）、数量、损耗、加工费、单价覆盖、软删除 | 唯一 `(unit_id, seq)`；`unit_id` 外键级联 |
| `packaging_templates` | 模板库 | 租户、模板 code、单元类型、名称、`schema_version`、`definition jsonb`、是否系统预置、启用 | 唯一 `(tenant_id, code)`；v1 只读 |
| `packaging_materials` | 材料库 | 租户、材料 code、名称、密度、采购单价、熏蒸、图纸颜色、适用单元类型数组、是否系统预置 | 唯一 `(tenant_id, code)`；空数组 = 全部单元可用 |
| `packaging_revisions` | 版本快照 | 所属方案、版本号、`snapshot jsonb`、合计、发布时间、发布人、备注 | 唯一 `(project_id, revision_no)`；只增不改 |

枚举：

- `PackagingUnitType`：`PALLET` / `CRATE` / `SKID` / `FRAME` / `DIVIDER` / `DUNNAGE` / `STEEL_STRAP`
- `PackagingProjectStatus`：`DRAFT` / `ISSUED` / `ARCHIVED`
- `PackagingPartRole`：`TOP_DECK` / `END_DECK` / `STRINGER_BOARD` / `BLOCK` / `BOTTOM_DECK` / `STRINGER` / `RUNNER` / `PLYWOOD` / `SPACER` / `PANEL` / `FRAME` / `BATTEN` / `STEEL_STRAP` / `DUNNAGE` / `CUSTOM`
- `PackagingOrientation`：`X` / `Y`
- `PackagingDestination`：`EXPORT` / `DOMESTIC`
- `PackagingLoadType`：`UNIFORM` / `CONCENTRATED`

通用字段（主键、`tenant_id`、`created_at/updated_at`、`deleted_at`）按技术方案 §5.1；`tenant_id` 不建外键，与现有业务表一致。

**更新口径**：

- 工作台只更新当前单元：`POST` 首次保存 / `PUT` 后续保存都只提交一个单元；API 契约仍接受数组（结构 1:n），1:1 工作台发送长度 1 的数组。
- 单元配置存 `packaging_units.params`（JSONB），不新增列：托盘 `params.deck = { top: { mode, count }, bottom: { mode, count } }`；木箱 `params.steelStrapCount` 与尺寸参数平铺。服务端原样保存，版本快照随单元数组保存。
- 构件来源不落库：读取时用「配置派生默认值」与「当前构件」逐字段比较得出 `auto / manual` 与覆盖字段；旧数据缺少配置时按构件数量反推。
- 服务端仍按整单重算：收到数组后先物理删除该方案的单元与构件，再按数组重建；版本快照独立保存，不受影响。
- 方案删除 = 软删除；单元与构件随方案不可见，不做物理删除以外的额外清理。
- 已发布（`ISSUED`）与已归档（`ARCHIVED`）方案的设计数据只读；要改必须新建下一版本（本轮未提供），旧版本快照不动。
- 存量 e2e 多单元测试数据删除（含单元与版本级联），不做产品数据迁移；新方案固定 1 个当前单元。

## 3. 模板机制

### 3.1 模板定义

`packaging_templates.definition` 为 JSON，结构：

```json
{
  "schemaVersion": 1,
  "structure": { "builder": "crate", "roles": ["runner", "bottomDeck", "panel", "frame", "topDeck", "steelStrap"] },
  "config": [
    {
      "key": "thicknessMm",
      "label": "面板厚",
      "group": "箱体尺寸",
      "type": "int",
      "min": 1,
      "default": 15
    }
  ],
  "params": [
    { "key": "lengthMm", "label": "内长", "type": "int", "min": 1, "default": 1200 }
  ],
  "derived": {
    "outer": {
      "length": "innerLengthMm + 2 * (thicknessMm + frameThicknessMm)",
      "width": "innerWidthMm + 2 * (thicknessMm + frameThicknessMm)",
      "height": "baseHeightMm + bottomThicknessMm + innerHeightMm + thicknessMm"
    },
    "parts": "deriveCrateParts"
  },
  "parts": [
    {
      "role": "PANEL",
      "name": "侧板",
      "materialCode": "PINE",
      "orientation": "X",
      "length": "innerLengthMm",
      "width": "thicknessMm",
      "thickness": "innerHeightMm",
      "quantity": "2",
      "wastePct": "0.08"
    }
  ],
  "layouts": [
    { "role": "PANEL", "axis": "Z", "distribute": "stack", "gap": "0" }
  ],
  "rules": [
    { "type": "requireRole", "role": "BOTTOM_DECK", "message": "至少一个底座承重构件" }
  ],
  "views": ["TOP", "FRONT", "SIDE", "ISO"]
}
```

- `structure` 描述单元类型与构件角色；`config` 描述用户可调参数（含分组、顺序、范围、选项）；`derived` 描述外尺寸公式与构件派生入口；`parts` 仅用于仍以模板行定义的单元，木箱 G 型改用 `deriveCrateParts`，不重复维护构件行。
- `config` 字段：`key` / `label` / `group` / `type`（`int` / `number` / `select` / `deck`）/ `min` / `max` / `default` / `options` / `help`。左栏按 `group` 分组、按数组顺序渲染；`select` 从 `options` 取选项；`deck` 渲染上 / 下铺板模式与数量。
- 托盘与木箱模板都带 `config`：托盘含外形尺寸、进叉方向与上下铺板；木箱含箱体尺寸、进叉方向与钢带数量；钢带箱含无框架选项、钢带数量 / 宽度 / 方向；框架箱含框架尺寸、面板覆盖与盖板开关；围板含层高 / 层数 / 板厚 / 搭接 / 铰链；垫木含单根尺寸 / 数量 / 排列。新增配置只改模板数据。
- 参数、配置、派生规则、布局、校验、视图均为数据；新增箱型优先加模板记录，需要专属几何时再注册构建器。
- 工作台左栏的单元目录由模板库驱动：父级 = 七个已实现单元类型（`PALLET` / `CRATE` / `SKID` / `FRAME` / `DIVIDER` / `DUNNAGE` / `STEEL_STRAP`），子级 = 该类型的模板；未实现类型不展示，避免出现空目录。
- `template_code` 在租户内唯一；系统预置模板 `is_system = true`。
- `schema_version` 用于后续模板结构升级；解释器拒绝未知版本。

### 3.2 受限表达式

`packages/shared/src/design/expression.ts` 提供纯函数求值：

- 变量：模板参数与常量（`lengthMm`、`widthMm`、`thicknessMm` 等）。
- 运算：`+ - * / %`、括号、比较与三元（仅用于数量与尺寸）。
- 函数：`min` / `max` / `ceil` / `floor` / `round` / `abs`。
- **禁止** `eval`、`Function`、属性访问、字符串拼接与任意代码执行。
- 解析为 AST 后求值；非法表达式在模板保存 / 读取时返回 `PACKAGING_TEMPLATE_INVALID`。

### 3.3 解释与构建

派生入口按单元类型分派，均输出同一 `PalletGeometry`，图纸与 BOM 消费几何结果：

| 单元 | 派生入口 |
| --- | --- |
| `PALLET` | `buildPalletGeometry`（`pallet.geometry.ts`） |
| `CRATE` / `SKID` / `STEEL_STRAP` | `deriveCrateOuter` / `deriveCrateParts` / `buildCrateGeometry`（`design/crate.ts`） |
| `FRAME` | `deriveFrameOuter` / `deriveFrameParts` / `buildFrameGeometry`（`design/frame.ts`） |
| `DIVIDER` | `deriveDividerOuter` / `deriveDividerParts` / `buildDividerGeometry`（`design/divider.ts`） |
| `DUNNAGE` | `deriveDunnageOuter` / `deriveDunnageParts` / `buildDunnageGeometry`（`design/dunnage.ts`） |

流程：

1. 按 `unit_type` 取模板定义，校验配置；
2. **派生在前、覆盖在后**：先由派生函数生成默认构件，再把手工覆盖（尺寸、数量、材料、费用）应用到对应行；
3. 由配置与覆盖后的构件生成 `PalletPiece[]`（位置、尺寸、角色、行号）；
4. 生成三视图、轴测与 2D / 3D 图元；展开图未实现；
5. 汇总 BOM 与校验结果；报价与开料属阶段五，未实现。

- 派生顺序固定：结构 → 配置 → 派生 → 覆盖；视图层不得重新推导外尺寸或构件。
- 单元类型特有的形状（如开槽纵梁槽口、木箱钢带绕箱、板条分缝）在各自派生文件内实现，不写进模板 JSON。
- 同一输入必须得到同一输出；前端预览与服务端重算使用同一组纯函数。

## 4. 几何、视图与图纸

### 4.1 几何

托盘几何在 `packages/shared/src/pallet.geometry.ts`，其余单元在 `packages/shared/src/design/`（`crate.ts` / `frame.ts` / `divider.ts` / `dunnage.ts`），统一输出：

```ts
interface PalletPiece {
  x: number; y: number; z: number;   // 左下后角，mm
  l: number; w: number; h: number;   // 长宽高，mm
  role: PalletComponentRole;
  componentIndex: number;            // 构件行号，与构件表 / 3D 选中联动
  label: string;
}
```

- 排布：构件行从上到下即物理层级；`z` = 下方全部构件高度之和。
- 面板 / 底板沿 X 或 Y 均分；纵梁 / 滑木按数量均分；墩块按网格均分；自定义构件按方向与数量均分。
- 木箱 G 型：底座、箱体、箱盖三层；外长 / 外宽 = 内 + 2 ×（面板厚 + 框架厚度），外高 = 内高 + 底板厚 + 盖板厚 + 底部支承高度。
- 木箱排布：滑木在 `z = 0` 沿 Y 均分；底板在支承顶面铺满外长 × 外宽；立柱在四角，位于底板与盖板之间；侧板沿 X 方向置于前后、端板沿 Y 方向置于左右，均按外轮廓扣减：侧板夹在立柱之间（起点 `frameT + 板厚`，长度 = 外长 − 2 ×（框架 + 板厚）），端板包住侧板（起点 `frameT`，长度 = 外宽 − 2 × 框架）；盖板在箱体顶部铺满外长 × 外宽；钢带按「绕箱体一圈」拆成四段薄带（竖带 + 顶带 + 底带），横向沿 X 均布、纵向沿 Y 均布并贴外表面。
- 构件尺寸即派生结果：侧板 = 内长 × 面板厚 × 内高，端板 =（内宽 + 2 × 面板厚）× 面板厚 × 内高（端板包侧板），底板 / 盖板 = 外长 × 外宽 × 对应板厚；手工覆盖只改该行，不改变外尺寸公式。
- 板面分条：侧板 / 端板 / 盖板按目标板宽 150mm 拆条，板条间留 2.5mm 工艺缝；底板保持整块。几何呈现真实拼板，BOM 仍按整板下料（拼条属加工工艺）。

### 4.2 2D 视图

| 视图 | x | y | 宽 | 高 |
| --- | --- | --- | --- | --- |
| top | `piece.x` | `piece.y` | `piece.l` | `piece.w` |
| front | `piece.x` | `H - z - h` | `piece.l` | `piece.h` |
| side | `piece.y` | `H - z - h` | `piece.w` | `piece.h` |

- 轴测：`u = (x - y) * 0.866`，`v = (x + y) * 0.5 - z`；按深度排序。
- 单视图统一 fit；三视图拼版为 2×2；尺寸标注由图纸模型统一生成。
- 画布内不绘制视图名称（主视图 / 俯视图 / 侧视图 / 轴测图），方向只由视图栏表达。
- 默认取景系数：单视图 `FIT_SCALE_SINGLE = 0.78`、三视图 / 分屏小图 `FIT_SCALE_MINI = 0.73`，避免默认顶满画布；手动缩放 / 复位不受影响。
- 2D 视图右下角固定操作提示（`text-wb-meta`）：「左键拖拽平移 · 滚轮缩放 · 点击构件选中」，与 3D 提示同位置同风格；分屏左窗不重复显示。
- 构件颜色按 `PackagingPartRole` 固定；选中描边 `#b83e38`、宽 2.5，并叠加 14% 选中色填充与 2.5px 同色光晕；普通描边 `#694a2f`、宽 0.8。
- 3D 选中：选中构件 emissive 强度 0.4，并在其包围盒上叠加选中色线框（不被遮挡），切换选中时重建；点击空白处取消选中。构件表选中行使用 `bg-primary/8`，与画布 / 图纸联动。

### 4.4 3D 场景

`packages/shared/src/pallet.scene.ts` 只产出 mesh 描述，不依赖 Three.js：

- 普通构件 = `box`；开槽纵梁 = `notchedStringer`；木箱钢带 = 四段 `box`（竖带 / 顶带 / 底带）环绕箱体，不生成贯穿实体。
- 材质：木质构件使用程序化木纹（CanvasTexture，按构件尺寸设置重复），钢带使用低粗糙度金属材质；半球光 + 主光 + 冷色补光。不绘制地面与阴影，任意视角背景保持干净。
- 交互：左键拖动旋转、滚轮缩放、右键平移；按下与抬起位移大于 4px 视为旋转，不触发构件选中；点击构件选中，点击空白取消选中。
- 正交相机、Z 轴向上、`OrbitControls`、Raycaster 选中联动。
- 默认取景放大 `DEFAULT_CAMERA_ZOOM = 1.15`；「复位」同时恢复相机位置、目标点与缩放，保证滚轮 / ± 之后能回到默认大小。
- WebGL 不可用回退 2D 轴测图。
- 3D 是派生视图，不是数据源；导出 OBJ / STL 消费同一份 mesh 描述。

### 4.5 滑木箱（R-019）

- `SKID` 复用 `design/crate.ts` 的派生与几何：`CrateParams` 增加可选 `runnerCount` / `runnerWidthMm`（默认 3 / 90），`deriveCrateParts` 按配置生成滑木；外尺寸公式与 CRATE 相同。
- 模板 `skid-g` 的 `config` 增加滑木数量 / 宽度，`derived.parts` 指向 `deriveCrateParts`。
- 文档层把 `SKID` 视为 crate-like：`UnitDraft.unitType` 扩展到 `PALLET | CRATE | SKID | STEEL_STRAP`（后者见 §4.6）；派生、校验、几何、保存参数与结论面积均走木箱分支。
- 服务端 `calcUnit` 接受 `SKID` 并走木箱校验 / 几何；图纸与报告的 `unitType` 扩展到 `SKID`。
- 左栏目录新增「滑木箱」分组；保存后的结构锁定规则见 §9.2。
- 单测覆盖：滑木数量 2/3/4 的构件与几何、外尺寸、保存 / 读取、服务端创建与报告。

### 4.6 钢带箱（R-023）

- `STEEL_STRAP` 复用 `design/crate.ts` 的派生与几何；`CrateParams` 增加可选 `strapWidthMm` / `strapDirection`，`frameThicknessMm` 允许为 0（无木框架）。
- `deriveCrateParts`：钢带数量派生允许 0–6（防御上限）、宽度 10–60；UI 由模板 `config` 限制（普通木箱 / 滑木箱 / 框架箱 0–4、钢带箱 2–6）。`strapDirection = 'both'` 时横向取 `ceil(count / 2)`、纵向取 `floor(count / 2)`，纵向构件 `orientation: 'y'`、`lengthMm = 外长`、`widthMm = 钢带宽度`；横向钢带保持沿 X 包覆外宽。
- `buildCrateGeometry`：钢带拆成四段薄带环绕箱体（竖带贴外表面、顶带 / 底带压上下沿），横向沿 X、纵向沿 Y 均分；无框架时立柱不参与几何，侧板 / 端板直接沿外框分布。
- 模板 `steel-strap-g` 的 `config`：箱体尺寸（框架厚度 min 0、默认 0）、钢带数量 2–6、钢带宽度 20–40、钢带方向横向 / 纵横、进叉方向；`derived.parts` 指向 `deriveCrateParts`。
- 文档层把 `STEEL_STRAP` 视为 crate-like：`UnitDraft.unitType` 扩展到 `PALLET | CRATE | SKID | STEEL_STRAP`；新建草稿默认无框架、4 道钢带、30mm 宽、横向；`params` 保存 / 读取包含 `strapWidthMm` / `strapDirection` / `frameThicknessMm = 0`。
- 服务端 `calcUnit` 接受 `STEEL_STRAP` 并走木箱校验 / 几何；框架厚度读取允许 0，避免无框架箱被误判外尺寸不足；图纸与报告的 `unitType` 扩展到 `STEEL_STRAP`。
- 左栏目录新增「钢带箱」分组；保存后的结构锁定规则见 §9.2。
- 单测覆盖：无框架外尺寸、横纵钢带拆分与宽度、纵向钢带几何、保存 / 读取、服务端创建与报告。

### 4.7 框架箱（R-020）

- `FRAME` 使用独立 `design/frame.ts`：`FrameParams` = 内尺寸、框架厚度、底板厚、滑木高度 / 宽度、面板厚、面板覆盖、盖板开关、钢带数量。
- 外尺寸：长 / 宽 = 内 + 2 × 框架 +（有面板时 2 × 面板厚）；高 = 滑木 + 底板 + 内高 + 框架 +（有盖板时面板厚）。「全包」在盖板关闭时仍强制盖板。
- 派生构件：滑木 3、底板 1、立柱 4、上框梁 2、下框梁 2、侧框梁 2；面板覆盖「侧端 / 全包」时增加侧板 2 + 端板 2；盖板按开关（或全包）生成；钢带 0–4 道。
- `buildFrameGeometry`：滑木在 `z = 0`；底板在滑木顶面；立柱四角；上 / 下框梁沿 X 连接立柱；侧框梁沿 Y；面板位于框架内侧；盖板在框架顶部。
- 模板 `frame-g` 的 `config`：箱体尺寸、框架尺寸、面板与盖板、加固；`derived.parts` 指向 `deriveFrameParts`。
- 文档层把 `FRAME` 视为独立结构：`UnitDraft.unitType` 扩展到 `PALLET | CRATE | SKID | FRAME | STEEL_STRAP`；参数经 `params` 保存 / 读取；`params` 含 `panelCoverage` / `hasLid` / `panelThicknessMm`。
- 服务端 `calcUnit` 接受 `FRAME` 并走框架校验 / 几何；图纸与报告的 `unitType` 扩展到 `FRAME`。
- 左栏目录新增「框架箱」分组；保存后的结构锁定规则见 §9.2。
- 单测覆盖：默认无面板外尺寸、侧端 / 全包与盖板开关、立柱与框梁几何、保存 / 读取、服务端创建与报告。

### 4.8 围板与垫木（R-021 / R-022）

- `DIVIDER` 使用 `design/divider.ts`：`DividerParams` = 内长 / 内宽、单层高度、层数 1–3、板厚、搭接宽度、每层铰链数量 0–4。
- 围板外尺寸：长 / 宽 = 内 + 2 × 板厚；高 = 单层高度 × 层数。派生构件：长围板 2 × 层数、宽围板 2 × 层数、铰链（每层数量 × 层数）。
- `buildDividerGeometry` 按层叠放四块围板，铰链放在每层角部；不含底板、盖板与滑木。
- `DUNNAGE` 使用 `design/dunnage.ts`：`DunnageParams` = 单根长 / 宽 / 厚、数量 1–20、排列平行 / 交叉。
- 垫木外尺寸：平行 = 长 ×（数量 × 宽）× 厚；交叉 = 长 × 宽 ×（2 × 厚）。派生构件：平行为一组，交叉为上下两组。
- 模板 `divider-g` 与 `dunnage-g` 的 `config` 分别驱动围板尺寸 / 连接件与垫木尺寸 / 排列；`derived.parts` 指向各自的派生函数。
- 文档层扩展 `UnitDraft.unitType` 到七种类型；`params` 保存层高 / 层数 / 搭接 / 铰链与垫木单根尺寸 / 数量 / 排列。
- 服务端 `calcUnit` 接受 `DIVIDER` / `DUNNAGE` 并走各自校验 / 几何；图纸与报告的 `unitType` 同步扩展。

## 5. BOM、报价与开料

### 5.1 BOM

- 净体积 = `l × w × h × q / 1e9`，5 位小数。
- 采购体积 = 净体积 ×（1 + 损耗），5 位小数。
- 重量 = 采购体积 × 密度，1 位小数。
- 材料费 = 采购体积 ×（单价覆盖 > 0 ? 单价覆盖 : 材料单价），2 位小数。
- 加工费 = 数量 × 加工费，2 位小数。
- 方案合计 = 当前单元合计；服务端按收到的单元数组重算，前端只预览。
- 构件行带来源标记（`auto` / `manual`）与覆盖字段，BOM 与构件表可区分；来源由 `resolvePartSources` 计算，不单独存储。
- 净耗与含损分列：净体积用于体积对比，采购体积 = 净体积 ×（1 + 损耗）用于采购与材料费。
- CSV：`design/csv.ts` 的 `bomToCsv` / `cuttingToCsv`；首行带 BOM，Excel 可直接打开；工作台导出当前单元；API 兼容多单元数组时仍输出合计。

### 5.2 报价（P4）

- 材料费 + 加工费 + 税费 + 管理费 + 毛利；支持按方案汇总与按单元明细。
- 报价只在本域，不写 finance 流水。
- 本轮【待补】。

### 5.3 开料（P4）

- 按材料与规格汇总；考虑锯缝、修边、拼板。
- 输出排版图与开料清单；纯函数 + Web Worker，先不做通用优化器。
- 本轮【待补】。

### 5.4 结论分级（阶段三）

`packages/shared/src/design/conclusion.ts` 纯函数：

```ts
evaluatePackagingConclusion({
  unitType: 'PALLET' | 'CRATE' | 'SKID' | 'FRAME' | 'DIVIDER' | 'DUNNAGE' | 'STEEL_STRAP',
  targetLoadKg: number | null,
  loadType: 'uniform' | 'concentrated',
  lengthMm: number,
  widthMm: number,
  innerLengthMm?: number,
  innerWidthMm?: number,
  issues: PalletIssue[],
}): {
  level: 'excellent' | 'available' | 'adjust',
  areaM2: number,
  areaLoadKgM2: number | null,
  reasons: string[],
  disclaimer: string,
}
```

- 底面积：托盘 `lengthMm × widthMm`；木箱 `innerLengthMm × innerWidthMm`，除以 10⁶ 得 m²。
- 判定顺序：错误级校验 → 需调整；底面积无效 → 需调整；载荷为空 → 可用（未评估）；> 800 → 需调整；500–800 → 可用；≤ 500 → 优良。
- 提示级校验或集中载荷把「优良」降为「可用」；集中载荷追加「需确认支承位置与局部加固」。
- 阈值常量 `PACKAGING_CONCLUSION_THRESHOLDS` 与免责声明 `PACKAGING_CONCLUSION_DISCLAIMER` 由共享文件导出，工作台与报告只引用，不复制。
- 结论是只读派生结果，不写入 `packaging_units`，不新增接口。

8. 回滚：迁移脚本保留「旧表 → 新表」对照与反向脚本；验证通过后再清理备份。

## 11. 测试

- 纯函数单测（最高优先级）：
  - 表达式求值：四则、函数、非法表达式、除零；
  - 模板解释：托盘六模板、木箱 G 型默认构件；
  - 木箱派生：外尺寸（含面板、框架、底板、盖板、支承）、构件尺寸与数量、参数变化重算；

  - 垫木：平行外宽按数量累加、交叉上下两组与双层高度、数量不足校验；

  - 来源标记：派生默认值与构件逐字段比较，尺寸 / 数量 / 材料 / 费用变化标记手动，手动铺板模式标记手动；

  - 图纸：图元数量、图层、图号、DXF 输出快照；
  - BOM：手算样例、损耗、单价覆盖、合计；
  - 版本快照：同输入同输出、材料价变化不影响旧版本；
