# 账号与权限领域实现设计（auth）

> 定位：账号与权限领域的**实现设计**（How）。需求见 `product/账号与权限.md`（R-账号与权限-001）。
> 全局约定见技术方案 §4（模块边界）/ §5（数据模型）/ §6（API 契约）/ §8（认证与安全），本文件只写本领域落点，不重述约定。

---

## 1. 模块结构与职责

`modules/auth` 为平台机制模块（非业务模块），同样遵循技术方案 §4.1 四件套模板：

```
modules/auth/
├── auth.controller.ts   # login / refresh / logout / change-password
├── auth.service.ts      # 凭证校验、令牌签发与撤销、密码修改
├── dto/                 # 契约形状（@nestjs/swagger 装饰器 class，供 OpenAPI 生成）；运行时校验用 @mcc/shared 的 zod schema
├── auth.module.ts
└── index.ts             # 唯一公开出口
```

- 鉴权守卫（登录态与 scope 校验）是横切中间件，按技术方案 §1.1 归 `common/`，通过 auth 的公开接口消费凭证校验，不内嵌在 auth 模块内部重复实现。
- `user` 表归本模块（数据所有权，技术方案 §4.2）。

## 2. 数据模型概览

> 细节归 `packages/db/prisma/schema.prisma`（表结构唯一事实源，技术方案 §5），此处只列概览与约定。

| 表 | 字段要点 | 备注 |
| --- | --- | --- |
| `user` | 账号、`password_hash`、`role`（四值枚举）、`status`（启用 / 停用）、软删除字段 | 通用字段（主键、`created_at/updated_at`、`deleted_at`）按技术方案 §5.1 |
| `refresh_token` | 刷新令牌哈希、所属账号、过期时间、撤销状态 | 会话表；签发即建记录，撤销即删或置失效，服务端只存哈希 |

- **角色固定四值**：`ADMIN` / `SALES` / `FINANCE` / `WORKER`（矩阵见 `product/账号与权限.md` R-账号与权限-003）。
- **不预建角色表**：角色 → scope 映射集中在共享常量 `ROLE_SCOPES`（`@mcc/shared`），服务端守卫与前端菜单共用；未来切换为可配置角色时，仅替换映射来源为角色表，守卫与页面接口不变。
- **账号状态**：`status` 枚举 `ACTIVE` / `INACTIVE`；停用即不可登录并撤销全部刷新令牌；不做物理删除。
- **tenant_id 全表预留**（ADR-005）：当前恒为 `default`，唯一约束按租户复合——`(tenant_id, username)`、`(tenant_id, token_hash)`，唯一性判定由数据访问层统一附加租户条件，业务代码不手写。

## 3. 接口清单

> 契约由 NestJS 装饰器代码生成 OpenAPI（技术方案 §6.1 / ADR-006），本文不手写参数与响应细节，只列清单。

| 接口 | 路径 | 用途 |
| --- | --- | --- |
| login | `POST /api/v1/auth/login` | 校验账号密码，签发访问令牌 + 刷新令牌；停用账号拒绝 |
| refresh | `POST /api/v1/auth/refresh` | 凭刷新令牌换新访问令牌；账号停用或已删拒绝 |
| logout | `POST /api/v1/auth/logout` | 撤销刷新令牌，登出 |
| change-password | `POST /api/v1/auth/change-password` | 登录态下修改密码 |
| users-list | `GET /api/v1/users` | 账号列表（管理员；不含密码） |
| users-create | `POST /api/v1/users` | 新建账号（账号、初始密码、角色；租户内唯一） |
| users-status | `PATCH /api/v1/users/:id/status` | 启用 / 停用（不能停用自己、不能停用最后一个启用管理员；停用撤销刷新令牌） |
| users-role | `PATCH /api/v1/users/:id/role` | 改角色（不能降级最后一个启用管理员；撤销刷新令牌） |
| users-reset-password | `POST /api/v1/users/:id/reset-password` | 管理员重置密码（撤销该账号刷新令牌） |

登录类接口为重点限流对象（技术方案 §8.4）；`users-*` 全部要求 `account:manage`。

## 4. 令牌与「记住登录」

- **访问令牌**：短期（15 分钟）；web 端放 `Authorization: Bearer` 请求头，只存内存、不落任何持久存储。
- **刷新令牌**：长期；web 端走 httpOnly Cookie（不允许 JS 读取）；无 Cookie 端（如将来的 miniapp）由 refresh 接口响应体返回。
- **记住登录**：勾选 → 刷新令牌 30 天；不勾选 → 会话级（浏览器关闭即失效）。
- 密码存储强哈希（argon2 或等价方案）、全站 HTTPS（技术方案 §8.1）。

## 5. 登录失败锁定

连续失败 5 次锁定 15 分钟（需求口径见 `product/账号与权限.md`，可调整）。计数按账号维度存 **Redis 过期键**：TTL 即锁定时长，键过期自动解锁；锁定期间拒绝校验，防暴力破解。

## 6. 鉴权守卫（服务层）

- 校验统一在服务层守卫完成（技术方案 §8.2），前端不做安全判断。
- 守卫先解析访问令牌；再读取接口 / 控制器上的 `@RequireScopes(...)` 元数据，按 `ROLE_SCOPES` 判定；无权限返回 403 `FORBIDDEN`。未声明 scope 的登录态接口（如 change-password）只校验登录态。
- 审计日志复用同一套守卫：`audit:view` 仅 ADMIN 拥有，不设 `audit:manage`；查询接口声明 `@RequireScopes('audit:view')`。
- 账号停用与角色变更：停用立即拒绝登录并在 refresh 时拒绝；角色变更撤销该账号刷新令牌，访问令牌最多 15 分钟后自然失效。
- 管理员保护（服务端事务内校验）：不能停用自己；不能停用或降级最后一个 `ACTIVE` 管理员。

## 7. 前端实现节（web）

- **登录页**（纯组件，页面设计见 `product/账号与权限.md`）：提交 login，访问令牌存内存；刷新令牌经 httpOnly Cookie 自动携带。
- **API client 拦截**：请求遇 401 先调 refresh 重试一次，刷新失败清会话跳登录页。
- **路由守卫**：未登录访问一律跳转登录页；路由与守卫结构见 `design/平台布局.md`。
- **角色与菜单**：角色从访问令牌载荷读取，前端用共享 `ROLE_SCOPES` 判定可见性；侧边菜单、头像菜单项与页面入口按 scope 裁剪；直接访问无权限页面显示统一提示，不渲染页面内容。
- **财务联动与页内 Tab 的 scope**：销售单现结沿用 `order:manage`；收支汇总两个页内 Tab 沿用 `finance:view`；均不新增权限单元。
- **审计日志入口**：头像下拉在「账号管理」旁增加「审计日志」（`audit:view` 才可见）；角色权限说明弹窗增加「审计日志」列（仅管理员「查看」），矩阵仍由 `ROLE_SCOPES` 生成；路由 `/admin/audit-logs` 的 scope 见 `design/平台布局.md` §1.3。
- **账号管理页**（`/admin/users`）：按列表页模式组装——筛选区（账号模糊 + 查询，查询回第 1 页）、批量操作区（新建账号左对齐、角色权限说明右端）、表格区（`flex-1` + `containerClassName="h-full overflow-y-auto"` + sticky 表头，无多选列）、分页区（左下，第 x / y 页 · 共 n 条）；新建 / 重置密码 / 改角色弹窗约 520px；仅 `account:manage` 可见，入口在顶栏头像下拉。顶部「角色权限说明」打开只读弹窗，矩阵与角色说明分别由共享 `ROLE_SCOPES` / `ROLE_DESCRIPTIONS` 生成；新建与改角色弹窗在角色下拉下展示对应说明；头像菜单显示当前账号与角色。
