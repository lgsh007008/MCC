# 账号与权限领域实现设计（auth）

> 定位：账号与权限领域的**实现设计**（How）。需求见 `product/账号与权限.md`（R-账号与权限-001）。
> 全局约定见技术方案 §4（模块边界）/ §5（数据模型）/ §6（API 契约）/ §8（认证与安全），本文件只写本领域落点，不重述约定。

---

## 1. 模块结构与职责

`modules/auth` 为平台机制模块（非业务模块），同样遵循技术方案 §4.1 四件套模板：

```
modules/auth/
├── auth.controller.ts            # 租户用户 login / refresh / logout / change-password
├── auth.service.ts               # 租户凭证校验、令牌签发与撤销、密码修改
├── platform-auth.controller.ts   # 平台运营 /ops/auth/login|refresh|logout|change-password
├── platform-auth.service.ts      # 平台凭证校验与平台令牌
├── platform-users.controller.ts  # /ops/accounts 与租户管理员账号操作
├── users.controller.ts           # 租户账号列表 / 新建 / 启停 / 改角色 / 重置密码
├── users.service.ts              # 租户账号与额度校验
├── dto/                          # 契约形状（@nestjs/swagger 装饰器 class，供 OpenAPI 生成）；运行时校验用 @mcc/shared 的 zod schema
├── auth.module.ts                # imports: TenantModule、AuditModule
└── index.ts                      # 唯一公开出口
```

- 鉴权守卫（登录态与 scope 校验）是横切中间件，按技术方案 §1.1 归 `common/`，通过 auth 的公开接口消费凭证校验，不内嵌在 auth 模块内部重复实现。
- `users`、`refresh_tokens`、`platform_users`、`platform_refresh_tokens` 四张表归本模块（数据所有权，技术方案 §4.2）。
- **单向依赖**：本模块导入 tenant（登录解析租户、额度、有效功能）；tenant 不导入本模块。开通首管理员由平台前端两步编排。

## 2. 数据模型概览

> 细节归 `packages/db/prisma/schema.prisma`（表结构唯一事实源，技术方案 §5），此处只列概览与约定。

| 表 | 字段要点 | 备注 |
| --- | --- | --- |
| `users` | 账号、`password_hash`、`role`（四值枚举）、`status`（启用 / 停用）、软删除字段 | 通用字段（主键、`created_at/updated_at`、`deleted_at`）按技术方案 §5.1；`(tenant_id, username)` 唯一 |
| `refresh_tokens` | 刷新令牌哈希、所属账号、过期时间、撤销状态、签发时租户 epoch | 会话表；签发即建记录，撤销即删或置失效，服务端只存哈希 |
| `platform_users` | 账号（全局唯一）、`password_hash`、角色（`PLATFORM_ADMIN`）、状态 | 全局表，无 `tenant_id`；不计入租户账号数；不参与租户四角色矩阵 |
| `platform_refresh_tokens` | 刷新令牌哈希、所属平台账号、过期时间、撤销状态 | 全局表，无 `tenant_id`；与租户刷新令牌分表、分 Cookie |

- **角色固定四值**：`ADMIN` / `SALES` / `FINANCE` / `WORKER`（矩阵见 `product/账号与权限.md` R-账号与权限-003）。
- **不预建角色表**：角色 → scope 映射集中在共享常量 `ROLE_SCOPES`（`@mcc/shared`），服务端守卫与前端菜单共用；未来切换为可配置角色时，仅替换映射来源为角色表，守卫与页面接口不变。
- **账号状态**：`status` 枚举 `ACTIVE` / `INACTIVE`；停用即不可登录并撤销全部刷新令牌；不做物理删除。
- **tenant_id 全表预留并启用**（ADR-005 / ADR-012）：租户请求必须在上下文中携带 `tenantId`，缺失即拒绝；唯一约束按租户复合——`(tenant_id, username)`、`(tenant_id, token_hash)`；平台身份相关表为全局表，无 `tenant_id`，从租户扩展中排除。
- **平台身份**：`platform_users` 与 `platform_refresh_tokens` 独立于租户账号；平台角色当前仅 `PLATFORM_ADMIN`，scope 走 `platform:*` 命名空间。
- **租户 epoch**：`tenants.session_epoch` 在停用时递增；租户访问令牌与刷新令牌携带签发时的 epoch，守卫与刷新校验不一致即拒绝，保证停用后旧令牌不恢复。

| 接口 | 路径 | 用途 |
| --- | --- | --- |
| login | `POST /api/v1/auth/login` | 校验账号密码，签发访问令牌 + 刷新令牌；停用账号拒绝 |
| refresh | `POST /api/v1/auth/refresh` | 凭刷新令牌换新访问令牌；账号停用或已删拒绝 |
| logout | `POST /api/v1/auth/logout` | 撤销刷新令牌，登出 |
| change-password | `POST /api/v1/auth/change-password` | 登录态下修改密码 |
| users-list | `GET /api/v1/users` | 账号列表（管理员；不含密码） |
| users-create | `POST /api/v1/users` | 新建账号（账号、初始密码、角色；租户内唯一） |
| users-status | `PATCH /api/v1/users/:id/status` | 启用 / 停用（不能停用自己、不能停用最后一个启用管理员；停用撤销刷新令牌） |

| platform-refresh | `POST /api/v1/ops/auth/refresh` | 凭平台刷新令牌换访问令牌 |
| platform-logout | `POST /api/v1/ops/auth/logout` | 撤销平台刷新令牌 |
| platform-change-password | `POST /api/v1/ops/auth/change-password` | 平台账号改密 |

| platform-account-status | `PATCH /api/v1/ops/accounts/:id/status` | 启停平台账号（不能停用自己、不能停用最后一个启用平台管理员） |

## 4. 令牌与「记住登录」

- **访问令牌**：短期（15 分钟）；放 `Authorization: Bearer` 请求头，只存内存、不落任何持久存储；租户令牌 `aud = web`，平台令牌 `aud = ops`，守卫按受众拒绝跨端调用。
- **刷新令牌**：租户走 httpOnly Cookie `refresh_token`（Path `/api/v1/auth`）；平台走独立 httpOnly Cookie `ops_refresh_token`（Path `/api/v1/ops`）；两者不共用 Cookie，也不互相解析。
- **载荷**：租户令牌含 `sub`、`username`、`role`、`tenantId`、`tenantEpoch`；平台令牌含 `sub`、`username`、`role: PLATFORM_ADMIN`，无 `tenantId`。
- **记住登录**：勾选 → 刷新令牌 30 天；不勾选 → 会话级（浏览器关闭即失效）；两端同口径。
- **租户停用**：`tenants.session_epoch` 递增；刷新令牌校验 epoch，不一致即拒绝；访问令牌由守卫校验租户状态与 epoch，停用即时生效，最长 15 分钟兜底。
- 密码存储强哈希（argon2 或等价方案）、全站 HTTPS（技术方案 §8.1）。

## 5. 登录失败锁定

连续失败 5 次锁定 15 分钟（需求口径见 `product/账号与权限.md`，可调整）。租户登录按「租户编号 + 账号」计数，键为 `login:fail:{tenantCode}:{username}`；平台登录按平台账号计数，键为 `login:fail:ops:{username}`。TTL 即锁定时长，键过期自动解锁；锁定期间拒绝校验，防暴力破解。

## 6. 鉴权守卫（服务层）

- 校验统一在服务层守卫完成（技术方案 §8.2），前端不做安全判断。
- **两条身份流水线**：租户请求走 `AuthGuard`（`aud = web`）；平台请求走 `PlatformAuthGuard`（`aud = ops`）。受众不匹配一律 401/403；平台令牌不能访问 `/admin`、`/m` 业务接口，租户令牌不能访问 `/ops` 接口。
- 守卫先解析访问令牌；再读取接口 / 控制器上的 `@RequireScopes(...)` 元数据，按 `ROLE_SCOPES` 判定；无权限返回 403 `FORBIDDEN`。未声明 scope 的登录态接口（如 change-password）只校验登录态。
- **租户解析**：登录先按 `tenantCode` 调 tenant 的 `findByCode`；租户不存在 / 停用与账号密码错误统一返回同一提示；再 `runWithTenant` 校验账号；刷新时按令牌中的 `tenantId` 校验租户状态与 epoch。
- **租户状态**：`AuthGuard` 每次请求校验租户启用状态与 epoch；停用即时拒绝，旧访问令牌最长 15 分钟过期。
- **scope 两套命名空间**：租户 scope 按 `ROLE_SCOPES`（`ADMIN/SALES/FINANCE/WORKER`）；平台 scope 按 `PLATFORM_ROLE_SCOPES`（当前仅 `PLATFORM_ADMIN`），互不授予。
- **功能闸门**：common 的 `FeatureGuard` 读取 `@RequireFeature(...)`，经 tenant 的 `getEffectiveFeatures` 判定；不可用返回 403 `FEATURE_DISABLED`。顺序为登录 → 租户状态 → feature → scope；平台路由不经过功能闸门。
- **额度**：新建租户账号前经 tenant 的 `getQuota` 校验；账号数为未删除账号数（含停用），平台账号不计入；超限返回 409 `QUOTA_EXCEEDED`。
- **租户管理员操作**：平台运营查看 / 补建 / 重置租户管理员，全部在目标租户作用域内执行；不代登录。
- 审计日志复用同一套守卫：`audit:view` 仅 ADMIN 拥有，不设 `audit:manage`；查询接口声明 `@RequireScopes('audit:view')`。平台审计查询用 `@RequirePlatformScopes('platform:audit:view')`。
- 账号停用与角色变更：停用立即拒绝登录并在 refresh 时拒绝；角色变更撤销该账号刷新令牌，访问令牌最多 15 分钟后自然失效。
- 管理员保护（服务端事务内校验）：不能停用自己；不能停用或降级最后一个 `ACTIVE` 管理员；平台管理员同规则。

## 7. 前端实现节（web）

- **登录页**（纯组件，页面设计见 `product/账号与权限.md`）：提交 `{ tenantCode, username, password, rememberMe }`，访问令牌存内存；刷新令牌经 httpOnly Cookie 自动携带。
- **平台运营前端**：`/ops/login` 平台登录页；平台访问令牌存内存，刷新走 `ops_refresh_token`；独立 `opsApi` 客户端（base `/api/v1/ops`），401 时调 `/ops/auth/refresh` 重试一次；`/ops` 壳与菜单见 `design/平台布局.md`。
- **菜单裁剪**：租户端菜单按 **feature ∩ scope** 裁剪；平台端菜单按平台 scope 裁剪；功能关闭时隐藏入口，服务端仍返回 `FEATURE_DISABLED`。有效功能随 `login` 与 `refresh` 响应下发（响应体 `features`），前端只存内存并在刷新后重建菜单，不在 JWT 中冗余功能清单。
- **平台账号页**（`/ops/accounts`）：列表 + 新建 / 重置密码弹窗；仅 `platform:account:manage` 可见；入口在 `/ops` 菜单。
- **租户管理员区**：租户详情内展示 auth 提供的 `ADMIN` 列表与重置密码入口；数据经 `/api/v1/ops/tenants/:tenantId/admins`，页面只引用、不重述账号规则。
- **API client 拦截**：请求遇 401 先调 refresh 重试一次，刷新失败清会话跳登录页。
- **路由守卫**：未登录访问一律跳转登录页；路由与守卫结构见 `design/平台布局.md`。
- **角色与菜单**：角色从访问令牌载荷读取，前端用共享 `ROLE_SCOPES` 判定可见性；侧边菜单、头像菜单项与页面入口按 scope 裁剪；直接访问无权限页面显示统一提示，不渲染页面内容。
- **财务联动与页内 Tab 的 scope**：销售单现结沿用 `order:manage`；收支汇总两个页内 Tab 沿用 `finance:view`；均不新增权限单元。
- **生产与库存 scope**：`production:view/manage` 覆盖生产记录列表 / 详情与新建 / 编辑 / 删除；`inventory:view` 覆盖库存页、盘点记录列表 / 详情、期初只读，`inventory:manage` 覆盖期初设置与新建盘点；`profit:view` 覆盖销售单材料毛利（只读），仅管理员拥有，销售 / 财务 / 工人无；不设 `profit:manage`。
- **托盘设计 scope**：`pallet:view` 覆盖项目列表 / 详情、2D / 3D 图纸、材料目录与报告；`pallet:manage` 覆盖新建、编辑、复制、删除；管理员 / 销售 manage，财务 view，工人无。路由 `/admin/pallet-design`、`/[id]`、`/[id]/report` → `pallet:view`，`/new` → `pallet:manage`；服务端写接口同样按 manage 校验。
- **路由 scope**：`/admin/production/records` → `production:view`，`new` / `[id]/edit` → `production:manage`；`/admin/production/inventory`、`opening`（只读查看）→ `inventory:view`；`/admin/production/inventory/counts` 与 `counts/[id]` → `inventory:view`，`counts/new` → `inventory:manage`；期初保存接口由服务端按 `inventory:manage` 校验；移动路由同口径映射。
- **审计日志入口**：头像下拉在「账号管理」旁增加「审计日志」（`audit:view` 才可见）；角色权限说明弹窗增加「审计日志」列（仅管理员「查看」），矩阵仍由 `ROLE_SCOPES` 生成；路由 `/admin/audit-logs` 的 scope 见 `design/平台布局.md` §1.3。
- **账号管理页**（`/admin/users`）：按列表页模式组装——筛选区（账号模糊 + 查询，查询回第 1 页）、批量操作区（新建账号左对齐、角色权限说明右端）、表格区（`flex-1` + `containerClassName="h-full overflow-y-auto"` + sticky 表头，无多选列）、分页区（左下，第 x / y 页 · 共 n 条）；新建 / 重置密码 / 改角色弹窗约 520px；仅 `account:manage` 可见，入口在顶栏头像下拉。顶部「角色权限说明」打开只读弹窗，矩阵与角色说明分别由共享 `ROLE_SCOPES` / `ROLE_DESCRIPTIONS` 生成；新建与改角色弹窗在角色下拉下展示对应说明；头像菜单显示当前账号与角色。
