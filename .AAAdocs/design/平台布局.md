# 平台布局领域实现设计（platform）

> 定位：平台布局与导航领域的**实现设计**（How）。需求见 `product/平台布局.md`（R-平台布局-001）。
> 本领域**无后端模块**（见 `0-文档驱动开发机制.md` 领域的特殊情况），本文件仅含前端实现节。前端全局规范（设计令牌、组件库纪律、多端策略、数据与状态）见技术方案 §7。

---

## 1. 前端实现节（web）

### 1.1 布局壳组件组织（经典三区）

后台路由组（技术方案 §3.2 `apps/web/app/admin`）的共享 layout 承载三区壳，业务页面只实现主内容区，不各自拼壳：

- **侧边栏**：Logo 区 + 分组导航（分组可折叠，组件库现成折叠件）；折叠开关用 `SidebarFooter` 放在侧边栏底部（展开态「收起」+ 图标，折叠态只显示图标，`useSidebar().toggleSidebar`）
- **顶栏（两行）**：第一行为多标签页（`TabBar`，仅标题、当前标签高亮）+ 右侧账号头像下拉（修改密码、退出登录——行为归账号与权限，见 `design/账号与权限.md` 前端实现节）；第二行为面包屑；两行整体固定（不随内容区滚动）；不设当前页标题
- **主内容区**：按页面模式承载（列表页为筛选区 + 批量操作区 + 表格，表单/详情页为内容主体），不设页面标题；内容区滚动，边栏与顶栏固定
- **壳层高度**：`SidebarProvider` 外壳固定为一屏高（`h-svh overflow-hidden`），`SidebarInset` 由 flex 拉伸获得确定高度，`<main>` 以 `flex-1 overflow-y-auto` 作为**唯一页面滚动容器**——列表页的 `h-full` 弹性布局依赖该确定高度；页面主体不再引起 document 级滚动

### 1.2 路由与守卫结构

- admin 路由组统一挂登录态守卫：未登录一律跳转登录页（登录页归账号与权限领域，见 `product/账号与权限.md`）。
- 页面路由与菜单项一一对应，路由目录按菜单分组（业务领域）组织，与菜单表（`product/平台布局.md` R-平台布局-001）同步。

### 1.3 菜单配置来源

- 菜单清单（分组、菜单项、路由路径）为 **web 内静态配置**，集中在 admin 一处维护，随菜单表更新而更新；每项**必带图标**（折叠为图标栏时只显示图标，见 `product/平台布局.md` 整体布局）。
- **图标全局不重复**（`lib/nav.ts` 约定 + `lib/nav.spec.ts` 单测兜底）：首页、分组、菜单项之间不复用同一图标，避免折叠态无法区分。
- **折叠态层级表达**：图标栏下每个菜单项左侧画树状结构线——上半段竖线 + 横向支线（Tailwind 伪元素/绝对定位 span 实现，非额外依赖），竖线在最后一项中心收口；分组图标为树的根节点。
- 导航链接一律用 `next/link`（客户端导航），禁止原生 `<a>` 整页跳转——整页刷新会让侧栏折叠状态回到默认；`sidebar_state` cookie 由服务端 `admin/layout.tsx` 读取，作为 `SidebarProvider` 的 `defaultOpen`（组件库在切换时写入该 cookie）。
- 分组树状折叠用本地状态（默认全部展开）：展开态组标题为按钮（文字 + Chevron，展开时旋转），图标态为组图标按钮（tooltip 显示组名），点击均切换该组子项显隐。
- 单角色「销售」全权限，暂不做按角色的菜单渲染；待新增角色需求出现后，再评估改由服务端按 scope 下发（见 `product/账号与权限.md`）。

### 1.4 与设计令牌 / 组件库衔接

- 样式一律引用 `packages/tokens` 设计令牌 + shadcn/ui 组件（技术方案 §7.1 / §7.2）；壳组件禁止写死色值、字号、间距。
- **视觉基线的令牌落点**（`packages/tokens/src/shadcn.css`）：`--primary` / `--foreground` 取近黑、`--muted-foreground` 取 `0.52`、`--border` 取 `0.92`、`--input` 取 `0.90`、`--sidebar` 取 `0.98`（浅灰骨架）、`--radius` 取 `0.5rem`（此时 `rounded-md` = 6px、`rounded-lg` = 8px）。页面一律用令牌与工具类，不写十六进制色值。
- **视觉基线的组件落点**：共享 `components/ui/table.tsx` 统一表头浅灰底（`bg-muted`）、表头 40px、行高 44px（`h-11`）、单元格 `px-3`、全表 `tabular-nums`；表格卡片用 `rounded-lg`（8px），筛选区与批量操作区内联、不单独成卡；主内容区边距 `p-7`（28px）。页面只补字段与列口径，不覆盖表头底色与行高。
- **已知取舍**：输入框边框对比约 1.4:1，低于 WCAG 1.4.11 对控件边界 3:1 的建议；为保持纯白轻盈风格暂不加深，仅作为已知项记录，后续如需无障碍合规再单独调整 `--input`。
- **内部滚动条**：全局样式定义 `.scroll-area`（`app/globals.css`）——Chromium 走 `::-webkit-scrollbar`：宽/高 10px、轨道透明、滑块视觉约 4px（3px 透明边框收窄）、圆角，默认 `foreground` 15%，容器悬停或 `focus-within` 28%，滑块悬停 38%；Firefox 走 `@supports not selector(::-webkit-scrollbar)` 降级为 `scrollbar-width: thin` + 单色（无悬停态）。共享表格容器与主内容区显式加该类；标签栏不加，保持隐藏滚动条规则。
- 表单基座组件（下拉 `Select`、日期 `DatePicker`、确认 `ConfirmDialog`）一律用 `components/ui` 封装，底座为 `@base-ui/react`（无头、可访问性完整），不使用浏览器原生控件；实现细节以组件代码为准，本节不记录库版本与 props。

### 1.5 页面组装清单

页面模式（当前三种：列表 / 表单 / 详情，清单与规范以 `product/平台布局.md` 为准）由 `components/ui` 现有组件拼装，不新造页面级样式：

| 页面模式 | 组件拼装 |
| --- | --- |
| 壳层 | SidebarFooter 折叠按钮（`useSidebar().toggleSidebar`，展开态「收起」+ 图标、折叠态仅图标）、图标栏树状结构线（绝对定位竖线 + 支线）、`next/link`（菜单与面包屑客户端导航）、分组树状折叠（展开态组标题按钮 / 图标态组图标按钮，Chevron 方向指示）、BreadcrumbLink（面包屑逐级可点击，根节点为「首页」）、BreadcrumbPage（当前页纯文本）、页面面包屑上下文（页面经 `usePageCrumb` 注入页面标识，壳统一渲染） |
| 列表页 | Button（新建 / 查询 / 批量动作）、Input（文本筛选，字段组 = 标签左 / 控件右左右并排）、Select（应用内下拉筛选）、DatePicker（应用内日期筛选，含日期区间）、Checkbox（首列多选与表头本页全选）、Table 全家（表格，表体内纵滚、表头 sticky）、TableFooter（sticky 底部合计行）、lucide 图标按钮（查看 Eye / 编辑 Pencil / 删除 Trash2，配 aria-label 与 title）、lucide 方向箭头图标（排序方向）、Button outline（上一页 / 下一页 + 页码信息文本，居左）。整页弹性布局：页面根容器 `flex h-full min-h-0 flex-col`，表格卡片 `min-h-60 flex-1`，Table 传 `containerClassName="h-full overflow-y-auto"`（页面不滚动，只在表体内部纵向滚动） |
| 表单页 | Label + Input / Select（应用内下拉）/ DatePicker（应用内日期）/ Textarea（字段，Label 与控件左右并排，明细区用紧凑字号）、Button（保存 / 取消 / 增删明细行，行操作用图标按钮）、Table（明细区，containerRef + 限高内部滚动、表头 sticky） |
| 详情页 | Button（编辑 / 返回列表）、Table（主实体与关联表） |

- 组件一律出自 `components/ui`（技术方案 §7.2）：新组件先入库再使用；禁止页面内裸写原生控件（原生 select、`input[type=date]`、手写 table）或内联样式
- 上述两条交互纪律由 web 侧 ESLint 在 CI 强制：`no-alert` 禁原生弹窗；`no-restricted-syntax` 禁页面直接写原生 select 与日期输入（仅 `components/ui` 内部豁免）
- 样式只允许引用 `packages/tokens` 令牌与组件 className 能力，禁止写死色值 / 字号 / 间距
- 无横向滚动（`product/平台布局.md` 整体布局硬约束）：页面外层不得产生横向溢出，超宽表格与明细在自身容器内滚动

### 1.6 多标签页

规则（生成、标题、关闭、上限、保留）以 `product/平台布局.md`「多标签页」为准，本节只写实现：

- **状态模型**：`lib/tabs.ts` 定义纯逻辑（`TabsState = { tabs: [{ path, title, lastActiveAt }], activePath }`）+ reducer（`sync` / `close` / `restore` / `reset`），纯函数便于单测；`TabsProvider`（Context + `useReducer`）挂在 `AdminShell`，不引入第三方状态库
- **生成与激活**：壳监听 `usePathname()`，路径变化时 `sync`——已存在则更新 `lastActiveAt` 并激活，不存在则新增到末尾；浏览器前进后退、深链接直达同样生效
- **标题来源**：菜单项名（`nav.ts` 的 `findNavByPath`）+ 面包屑各级标题，以「 / 」拼接（如「销售单 / SO-2026-001 / 编辑」）；标题后到时由同一次 `sync` 回写到已存在的标签
- **数据缓存**：`@tanstack/react-query`（技术方案 §7.4 约定的查询库），`AppQueryProvider` 挂在 `AdminShell` 最外层；详情与编辑共用查询键 `['sale-order', id]`，`staleTime: 0` + `gcTime: 5 分钟`——切回标签先用缓存渲染，同时后台刷新，不出现整页加载态。列表页暂未接入（筛选/分页状态未持久化，切走即重置，列为后续改进）
- **滚动恢复**：主内容区 `<main>` 按 `pathname` 在内存 Map 记录 `scrollTop`，路径变化后 `requestAnimationFrame` 恢复；页面刷新不保留（标签本身随刷新恢复，滚动不恢复）
- **关闭**：仅单标签关闭（无关闭全部/其他）；关闭当前标签时按「右邻 → 左邻 → 首页」计算下一个激活路径并 `router.push`；关闭非当前标签只删除
- **上限与淘汰**：`MAX_TABS = 12`；新增前若已达上限，淘汰 `lastActiveAt` 最小且非首页的标签；首页（`/admin`）固定首位、不可关闭、不参与淘汰
- **持久化**：`sessionStorage` 存 `{ tabs, activePath }`（键名带版本），挂载时 `restore` 并校正非法数据；登出、改密成功后 `reset` 并清空存储
- **展示**：标签只显示标题（无图标），激活态浅底 + 文字加深；标签栏**隐藏滚动条**（`scrollbar-width: none` + WebKit 伪元素），溢出时两端出现左右切换按钮（`aria-label` 左移/右移标签，到边界禁用，点击按可视宽度 80% 滚动，`behavior: smooth`）；未溢出时不渲染按钮；激活标签用容器 `scrollLeft` 计算滚入（不用 `scrollIntoView`，避免连带滚动 document）；单标签最大宽度约 220px，超出省略，完整标题放 `title` 悬浮提示
- **宽度约束（无横向滚动）**：`SidebarInset`、`header`、标签行三层必须保留 `min-w-0`，右侧头像 `shrink-0`，单个标签 `shrink-0`；面包屑行 `min-w-0 overflow-hidden`，列表 `flex-nowrap`，项 `min-w-0 truncate` + `title`；E2E 在窄视口 + 多标签下断言 `documentElement/body.scrollWidth ≤ clientWidth` 防回归
- **无障碍**：容器 `role="tablist"`，标签 `role="tab"` + `aria-selected`，关闭按钮 `aria-label="关闭 <标题>"`；标签内容用按钮语义承载键盘操作
- **边界**：不做页面保活——表单未保存内容在切走标签后丢失；未知路径按当前面包屑/路径兜底生成标题

### 1.7 二次确认

规则（何时确认、文案、按钮与焦点）以 `product/平台布局.md`「二次确认规范」为准，本节只写实现：

- **共享组件**：`components/ui/confirm-dialog.tsx` 导出 `ConfirmProvider` 与 `useConfirm()`；Provider 挂在 `AdminShell` 的 Provider 栈内，全局只此一处
- **调用形态**：页面不维护 open 状态，直接 `const ok = await confirm({ title, description, confirmText, tone, onConfirm })`；`onConfirm` 在弹层内执行，执行期间按钮禁用并显示处理中；取消返回 false，成功返回 true，失败抛出由调用方处理
- **无障碍**：弹层 `role="alertdialog"`，标题与正文经 `aria-labelledby` / `aria-describedby` 关联；默认焦点落在「取消」；ESC 与点击遮罩等同取消
- **禁止原生弹窗**：`window.confirm / alert / prompt` 一律禁用，由 web 侧 ESLint `no-alert` 在 CI 拦截
- **失败处理**：`onConfirm` 抛错时关闭弹层并把错误抛给调用方，由页面以页内提示展示；不弹成功回执
- **批量与混合状态**：按钮可用性由页面按「将有变更的行数」计算，为 0 时禁用；确认正文给出将变更与跳过条数（口径见产品文档）
