# 生产与库存领域实现设计（production）

> 定位：生产与库存领域的**实现设计**（How）。需求见 `product/生产与库存.md`（R-生产-001~005）。
> 全局约定见技术方案 §4（模块边界）/ §5（数据模型）/ §6（API 契约）/ §7（前端规范），本文件只写本领域落点，不重述约定。

## 1. 模块结构与职责

`modules/production` 为业务模块，遵循技术方案 §4.1 四件套模板：

```
modules/production/
├── production.controller.ts   # 原木领用 / 方木产出 / 库存汇总 / 期初 / 盘点
├── production.service.ts      # 编号、领用、产出、成本池、库存汇总、库存调整、当前成本
├── dto/
│   ├── production.dto.ts      # 原木领用 / 方木产出契约
│   └── inventory.dto.ts       # 库存 / 期初 / 盘点契约
├── production.module.ts       # exports: ProductionService
└── index.ts                   # 唯一公开出口
```

- `material_issues`、`production_outputs`、`production_output_lines`、`inventory_adjustments`、`inventory_adjustment_items` 归本模块。
- 成本池与库存为**实时聚合**，不落快照；库存调整单是唯一手工变动入口。
- 成本计算纯函数放 `packages/shared`（`inventory.calc.ts`），服务端与测试共用。
- 销售单成本快照字段归 order 域（`sale_orders`）；本模块只提供「当前方木平均成本」计算服务。
- 本模块**不导入** OrderModule / PurchaseModule，避免与 order 现结联动形成环；库存聚合对 `sale_orders`、`sale_order_items`、`purchase_orders` 做**只读查询**（与 finance 应收应付只读聚合同一口径），不写对方表。

### 2.1 物料模型定位与主流 ERP 对比

本期采用 **Route A 简化模型**：原木 = 原材料、方木 = 成品，净尺寸（长 / 宽 / 高，整数 mm）即隐式 SKU；原木池与方木池各一个移动加权平均成本，全厂方木共用一个平均成本。

| 维度 | 主流 ERP（SAP / 用友 / 金蝶等） | 本期（Route A） |
| --- | --- | --- |
| 物料主数据 | 物料编码 + 分类 + 计量单位 + 规格特性（批次 / 序列号） | 不建主数据；原木只有吨，方木以净尺寸三元组标识 |
| 仓库与库位 | 多仓库 / 库位 / 调拨 / 盘点范围 | 单仓隐含；无库位、无调拨 |
| 成本核算 | 按物料 / 规格 / 批次分别核算，支持标准成本与差异分析 | 原木池 + 方木池两个池，移动加权平均；不按规格分摊 |
| 盘点流程 | 选范围 → 生成盘点表（盲盘）→ 录实盘 → 差异复核 → 生成调整单 → 原因代码 | 选类型（原木 / 方木）→ 实盘留空 → 差异复核 → 生成 `IC` 调整单 → 原因选填 |

**Route A 的取舍**

- 优点：不建主数据与仓库体系，上线快；吨 / 方两把尺子足够支撑采购、生产、销售与库存估值；成本池只有两个，口径简单可复现。
- 代价：不同规格共用方木平均成本，规格间毛利差异看不出来；无批次与库位，追溯只能到单据层；盘点以规格为行，规格变多后录入成本上升。

**两级升级路径**（本期不推进，按需另立需求与 ADR）

1. **按规格核算成本**：方木池按净尺寸规格拆分，规格各自维护数量与金额；仍不建物料主数据，规格由生产 / 销售自动扩展。
2. **完整物料主数据**：建物料主数据（编码、分类、计量单位、规格特性）、多仓库 / 库位、批次与序列号，成本按物料 + 批次核算，盘点按范围生成盘点任务。

## 3. 计算规则（纯函数，`packages/shared/src/inventory.calc.ts`）

### 3.1 成本池

- 原木池：数量（吨，3 位）、金额（元，2 位）、平均成本（元/吨，内部 6 位）。
- 方木池：数量（m³，4 位）、金额（元，2 位）、平均成本（元/m³，内部 6 位）。
- 待结转池：金额（元，2 位），无数量、无平均成本；不计入库存总值。
- 全厂方木共用一个成本池；不同规格共用同一平均成本。
- 事件按「业务日期升序 → 创建时间升序 → 编号升序」排序；期初固定最前；产出必须排在其对应领用之后。
- 采购：原木数量 += 送货吨数；原木金额 += 采购合计金额。
- 原木领用：领用成本 = 领用吨数 × 当前原木平均成本；原木数量 -= 领用吨数；原木金额 -= 领用成本；待结转金额 += 领用成本；方木池不变。
- 方木产出：方木数量 += 产出方数；方木金额 += 当前待结转金额；待结转金额清零；方木平均成本此时才更新。
- 销售：销售成本 = 方木方数 × 当前方木平均成本；方木数量 -= 方木方数；方木金额 -= 销售成本。
- 期初：按原木 / 方木明细加数量与金额；待结转为 0。
- 盘点：按差异数量 × 当前对应平均成本调整数量与金额；差异金额进「盘点损益」；待结转不参与盘点。
- 数量 ≤ 0 或金额 ≤ 0 时，平均成本沿用最近一次有效值；无有效值按 0；页面标「估算 / 成本待补」。
- **逐单归属（只用于追溯）**：折叠时维护一个按事件顺序排列的领用队列（每笔领用记 `ref` 与剩余待结转金额）；产出时从队首依次扣减并记录来源，直到本次应结转金额分配完。输出每笔领用的已结转 / 待结转（及结转过它的产出单 `ref`）与每张产出单的本次结转金额（及来源领用单 `ref`）。队列剩余之和恒等于待结转池总额，不参与任何金额计算。
- 金额与数量全部以字符串 + BigInt 放大整数计算，禁浮点；内部成本 6 位，展示按「金额 2 位、其余数字（吨数 / 方数 / 平均成本）3 位」四舍五入。

### 3.2 库存汇总

- 原木库存 = 期初 + 采购送货 − 原木领用 + 盘点差异。
- 方木库存 = 期初 + 方木产出 − 销售出库 + 盘点差异；按净尺寸规格聚合。
- 待结转金额 = Σ原木领用成本 − Σ产出结转成本；领用后增加、产出后清零，盘点不调整。
- 逐单归属结果（`issueSettlements` / `outputSettlements`）由同一个折叠函数返回，按 `ref`（单据编号）索引；状态由金额推导：`remaining = 0` → `settled`，`remaining = cost` → `pending`，其余 → `partial`。
- 库存总值 = 原木池金额 + 方木池金额，不含待结转；成本守恒 = 原木池 + 待结转 + 方木池。
- 期初日期之前的采购 / 生产 / 销售 / 调整不参与计算。
- 无期初时返回 `needsOpening = true`，库存为 0，页面引导先设期初。

### 3.3 销售单材料成本快照

- `sale_orders.material_unit_cost` 记录下单时方木平均成本；`material_cost_amount` = 总方量 × 单价；`material_cost_status` = `FINAL`（单价 > 0）或 `PENDING`。
- 方木平均成本在方木产出保存时才更新；领用后未产出期间，销售沿用现有方木平均成本，不再出现临时偏高。
- 新建：order 在保存前调用 `ProductionService.currentTimberUnitCost()`，把返回值写入快照。
- 更新：状态 `FINAL` 时按原快照单价 × 新方量重算金额；状态 `PENDING` 时尝试取当前成本，仍无成本则保持 `PENDING`、金额 0。
- 重算：仅 `PENDING` 订单，管理员 / 销售手动触发；取当前成本，写入快照并置 `FINAL`；已 `FINAL` 返回 409。
- 快照写入后不随采购 / 生产成本变化；库存估值仍是当前值。

### 3.4 材料毛利

- 确认收入：现结取实收金额，赊销取合计金额。
- 材料毛利 = 确认收入 − `material_cost_amount`；`PENDING` 时毛利与毛利率返回 `null`，页面显示「成本待补」。
- 毛利率 = 材料毛利 ÷ 确认收入 × 100，2 位小数；收入为 0 返回 `null`。
- 不含人工与费用，不进入 finance 收支汇总。

### 3.5 盘点录入规则

- **单类型**：`targetType` = `RAW_LOG` / `TIMBER` 二选一，一张盘点单只含一类明细；类型由新建入口带入，保存后不可改。
- **实盘留空**：`actualQuantity` 可空；留空行不参与计算、不生成调整明细；整单没有已填行时返回 400（`COUNT_NO_LINES`）。
- **只统计已填行**：差异 = 实盘 − 账面；差异为 0 的行同样不生成明细。
- **盘盈 / 盘亏**：由差异正负决定（正 = 盘盈、负 = 盘亏），不落独立字段；列表的盘盈 / 盘亏项数按差异符号统计。
- **原因可选**：`reason` 为空时按 `OTHER` 落库；枚举只有 `MEASUREMENT` / `MISSING` / `DAMAGE` / `OTHER`，不含盘盈 / 盘亏。
- **日期校验**：`countDate` 不得早于期初日期（`COUNT_BEFORE_OPENING`），不得晚于今天（`COUNT_IN_FUTURE`）；未设期初时按 `COUNT_BEFORE_OPENING` 提示先设期初。
- **立即生效**：保存成功即写入 `inventory_adjustments` + `inventory_adjustment_items`，库存汇总下一次查询即反映差异，无异步任务。
- **待结转**：盘点只调整原木或方木成本池，待结转金额不变；方木盘点差异按当前方木平均成本计价。

## 6. 跨模块边界

- **只读聚合**：本模块为计算库存与成本，只读查询 `purchase_orders`、`sale_orders`、`sale_order_items`；不写对方表、不注入对方 Service。与 finance 应收应付只读聚合同一口径，避免 order → production → order 的模块环。
- **order → production**：OrderModule 导入 ProductionModule，保存销售单前调用 `currentTimberUnitCost()`；ProductionModule 不导入 OrderModule。
- **purchase**：采购单保存即入库；本模块按送货吨数与采购合计金额聚合原木库存，采购单不写库存表。
- **finance**：库存估值与材料毛利不进入收支汇总；本期不做联动。
- **audit**：原木领用、方木产出与库存调整的写操作经全局审计拦截器落库；recalculate-cost 在 order 控制器声明 `@AuditAction`。

## 7. 前端实现节（web）

### 7.1 PC

- 原木领用列表 `/admin/production/issues`：列表页模式；标准日期筛选条（领用日期区间）+ 结转状态下拉（全部 / 待结转 / 已结转，写入 query）；列 = 编号、领用日期、领用吨数、结转状态、备注、创建时间；首列多选 + 批量删除；合计行领用吨数；结转状态为纯文本，与正文同字号同色（不用红色、不用徽标）。
- 原木领用新建 / 编辑 `/admin/production/issues/new`、`/[id]/edit`：`PageFrame`；字段 = 领用日期（`w-40`）、领用吨数（`w-40`）、备注（单列、`max-w-72`）；保存 / 取消固定操作区。
- 原木领用详情 `/admin/production/issues/[id]`：`PageFrame`；标题编号；信息条 = 领用日期、领用吨数、结转状态、已结转金额、待结转金额、创建时间、备注；有结转时增加「结转来源」行，以纯文本列出全部产出单编号（不跳转）；结转状态为纯文本、不用红色；操作 = 编辑 / 返回列表；删除只在列表行操作。

### 7.3 销售单材料毛利

- order 详情页在 `profit:view` 时请求 `GET /sale-orders/:id/profit`，展示材料毛利卡；`profit:manage` 且状态 `PENDING` 时显示「重算材料成本」，二次确认后调 `POST /sale-orders/:id/recalculate-cost`。

- 材料毛利卡标题右侧放「口径说明」链接按钮（`MaterialProfitHelpDialog`），PC 与移动均挂载。
- 销售单保存前的成本提示：`apps/web/lib/timber-cost.ts` 的 `hasNoValidTimberCost()` 查库存汇总（未设期初或方木单位成本为 0），`isMaterialCostPending(orderId)` 查材料毛利状态；新建单直接检查，编辑单仅在「成本待补」时检查；命中后 `useConfirm` 二次确认（标题「当前无有效方木成本」，确认按钮「仍然保存」），取消则中止保存，确认后照常提交；PC 与移动两个销售单表单共用。
