# 生产与库存领域实现设计（production）

> 定位：生产与库存领域的**实现设计**（How）。需求见 `product/生产与库存.md`（R-生产-001~005）。
> 全局约定见技术方案 §4（模块边界）/ §5（数据模型）/ §6（API 契约）/ §7（前端规范），本文件只写本领域落点，不重述约定。

## 1. 模块结构与职责

`modules/production` 为业务模块，遵循技术方案 §4.1 四件套模板：

```
modules/production/
├── production.controller.ts   # 原木领用 / 方木产出 / 库存汇总 / 期初 / 盘点
├── production.service.ts      # 编号、领用、产出、成本池、库存汇总、库存调整、当前成本
├── dto/
│   ├── production.dto.ts      # 原木领用 / 方木产出契约
│   └── inventory.dto.ts       # 库存 / 期初 / 盘点契约
├── production.module.ts       # exports: ProductionService
└── index.ts                   # 唯一公开出口
```

- `material_issues`、`production_outputs`、`production_output_lines`、`inventory_adjustments`、`inventory_adjustment_items` 归本模块。
- 成本池与库存为**实时聚合**，不落快照；库存调整单是唯一手工变动入口。
- 成本计算纯函数放 `packages/shared`（`inventory.calc.ts`），服务端与测试共用。
- 销售单成本快照字段归 order 域（`sale_orders`）；本模块只提供「当前方木平均成本」计算服务。
- 本模块**不导入** OrderModule / PurchaseModule，避免与 order 现结联动形成环；库存聚合对 `sale_orders`、`sale_order_items`、`purchase_orders` 做**只读查询**（与 finance 应收应付只读聚合同一口径），不写对方表。

### 2.1 物料模型定位与主流 ERP 对比

本期采用 **轻量批次模型**：原木 = 原材料、方木 = 成品，净尺寸（长 / 宽 / 高，整数 mm）即隐式 SKU；原木池全厂一个移动加权平均成本，方木按生产批次分别核算，批次之间不混摊。

| 维度 | 主流 ERP（SAP / 用友 / 金蝶等） | 本期（轻量批次） |
| --- | --- | --- |
| 物料主数据 | 物料编码 + 分类 + 计量单位 + 规格特性（批次 / 序列号） | 不建主数据；原木只有吨，方木以净尺寸三元组标识 |
| 仓库与库位 | 多仓库 / 库位 / 调拨 / 盘点范围 | 单仓隐含；无库位、无调拨 |
| 成本核算 | 按物料 / 规格 / 批次分别核算，支持标准成本与差异分析 | 原木一个池；方木按批次一个池，批次内移动加权平均；不按规格分摊 |
| 盘点流程 | 选范围 → 生成盘点表（盲盘）→ 录实盘 → 差异复核 → 生成调整单 → 原因代码 | 选类型（原木 / 方木）→ 实盘留空 → 差异复核 → 生成 `IC` 调整单 → 原因选填；方木差异按批次 FIFO 分摊 |

**轻量批次的取舍**

- 优点：批次作为成本对象，老库存与新批次成本不混摊；销售按批次 FIFO 扣层，成本可追溯；不建物料主数据与仓库体系，上线仍快。
- 代价：批次内仍可能因多张产出单出现“第一张拿走全部待结转”；盘点差异按 FIFO 分摊是简化；不做 BOM、工序、人工与制造费用。
- 升级路径：完整物料主数据 + BOM + 工单 + 人工 / 制造费用 + 批次质检 / 保质期，按需另立需求（ADR 按用户决定不新增）。

## 3. 计算规则（纯函数，`packages/shared/src/inventory.calc.ts`）

### 3.1 成本池

- 原木池：全厂一个；数量（吨，3 位）、金额（元，2 位）、平均成本（元/吨，内部 6 位）。
- 批次方木池：每个生产批次一个；数量（m³，4 位）、金额（元，2 位）、平均成本（元/m³，内部 6 位）。
- 批次待结转：每个生产批次一个；金额（元，2 位），无数量、无平均成本；不计入库存总值。
- 方木批次之间不混摊；同一批次内不同规格共用批次平均成本。
- 事件按「业务日期升序 → 创建时间升序 → 编号升序」排序；期初固定最前；批次关闭事件按关闭时间排序；产出必须排在其对应领用之后。
- 采购：原木数量 += 送货吨数；原木金额 += 采购合计金额。
- 原木领用：领用成本 = 领用吨数 × 当前原木平均成本；原木数量 -= 领用吨数；原木金额 -= 领用成本；本批次待结转 += 领用成本；方木池不变。
- 方木产出：本批次方木数量 += 产出方数；本批次方木金额 += 本批次待结转金额；本批次待结转清零；批次平均成本此时才更新。
- 批次关闭：本批次待结转全额转入本批次方木金额；待结转清零；状态置 `CLOSED`。
- 销售：按批次日期先进先出、且只扣有该规格库存的批次；每层成本 = 扣层方数 × 该批次平均成本；方木数量与金额同步扣减；批次不足部分进「负库存缺口」，按当前全厂加权成本估算。
- 期初：原木进原木池；方木按期初库存批次加数量与金额；待结转为 0。
- 盘点：按差异数量 × 当前成本计价；方木差异按批次日期 FIFO 分摊到各批次；差异金额进「盘点损益」；待结转不参与盘点。
- 数量 ≤ 0 或金额 ≤ 0 时，平均成本沿用最近一次有效值；无有效值按 0；页面标「估算 / 成本待补」。
- **批内逐单归属（只用于追溯）**：每个批次维护一个按事件顺序排列的领用队列（每笔领用记 `ref` 与剩余待结转金额）；产出时从队首依次扣减并记录来源。输出每笔领用的已结转 / 待结转与每张产出单的本次结转金额及来源领用单。队列剩余之和恒等于该批次待结转金额，不参与任何金额计算。
- 金额与数量全部以字符串 + BigInt 放大整数计算，禁浮点；内部成本 6 位，展示按「金额 2 位、其余数字（吨数 / 方数 / 平均成本）3 位」四舍五入。

### 3.2 库存汇总

- 原木库存 = 期初 + 采购送货 − 原木领用 + 盘点差异。
- 方木库存 = 期初 + 方木产出 − 销售出库 + 盘点差异；按净尺寸规格聚合，同时按批次分别记录。
- 待结转金额 = Σ各批次（领用成本 − 产出 / 关闭结转成本）；领用后增加、产出或关闭后清零，盘点不调整。
- 逐单归属结果（`issueSettlements` / `outputSettlements`）由同一个折叠函数返回，按 `ref` 索引，并带 `batchRef`；状态由金额推导：`remaining = 0` → `settled`，否则 `pending`（产出与关闭均为全额结转，无部分结转）。
- 库存总值 = 原木池金额 + Σ批次方木池金额，不含待结转；成本守恒 = 原木池 + Σ批次待结转 + Σ批次方木池。
- 每个批次返回 `timberVolume` / `timberAmount` / `timberUnitCost` / `pendingAmount` / `specs`；负库存缺口以 `shortfallVolume` / `shortfallAmount` 单独返回，不计入任何批次。
- 期初日期之前的采购 / 生产 / 销售 / 调整不参与计算。
- 无期初时返回 `needsOpening = true`，库存为 0，页面引导先设期初。

### 3.3 销售单材料成本快照

- `sale_orders.material_unit_cost` 记录加权平均单价；`material_cost_amount` = 各批次扣层金额合计；`material_cost_status` = `FINAL`（加权单价 > 0）或 `PENDING`。
- `sale_order_cost_layers` 记录每层来源批次、规格、扣层方数、单位成本与金额；负库存层批次编号为空字符串。
- 新建：order 在保存前调用 `ProductionService.calcSaleMaterialCost(items)`，返回金额、加权单价、状态与批次层；写入快照与层明细。
- 更新：状态 `FINAL` 时按原快照加权单价 × 新方量重算金额；方量变化时清空原层明细（层与方量不再对应）；状态 `PENDING` 时尝试取当前批次成本，成功则写入快照与层明细。
- 补录：不提供独立重算接口；仅 `PENDING` 订单在编辑保存销售单时，由 order 调用 `calcSaleMaterialCost(items, order.code)` 排除本单自身销售事件试算，成功则写入快照与层明细并置 `FINAL`。
- 快照写入后不随采购 / 生产 / 盘点变化；库存估值仍是当前值。

### 3.4 材料毛利

- 确认收入：现结取实收金额，赊销取合计金额。
- 材料毛利 = 确认收入 − `material_cost_amount`；`PENDING` 时毛利与毛利率返回 `null`，页面显示「成本待补」。
- 毛利率 = 材料毛利 ÷ 确认收入 × 100，2 位小数；收入为 0 返回 `null`。
- 不含人工与费用，不进入 finance 收支汇总。

### 3.5 盘点录入规则

- **单类型**：`targetType` = `RAW_LOG` / `TIMBER` 二选一，一张盘点单只含一类明细；类型由新建入口带入，保存后不可改。
- **实盘留空**：`actualQuantity` 可空；留空行不参与计算、不生成调整明细；整单没有已填行时返回 400（`COUNT_NO_LINES`）。
- **只统计已填行**：差异 = 实盘 − 账面；差异为 0 的行同样不生成明细。
- **盘盈 / 盘亏**：由差异正负决定（正 = 盘盈、负 = 盘亏），不落独立字段；列表的盘盈 / 盘亏项数按差异符号统计。
- **原因可选**：`reason` 为空时按 `OTHER` 落库；枚举只有 `MEASUREMENT` / `MISSING` / `DAMAGE` / `OTHER`，不含盘盈 / 盘亏。
- **日期校验**：`countDate` 不得早于期初日期（`COUNT_BEFORE_OPENING`），不得晚于今天（`COUNT_IN_FUTURE`）；未设期初时按 `COUNT_BEFORE_OPENING` 提示先设期初。
- **立即生效**：保存成功即写入 `inventory_adjustments` + `inventory_adjustment_items`，库存汇总下一次查询即反映差异，无异步任务。
- **待结转**：盘点只调整原木或方木成本池，待结转金额不变；方木盘点差异按当前成本计价，并按批次日期先进先出分摊到各批次；差异超过可售库存时剩余部分记入最后一个可分摊批次（没有则最早批次，允许批次数量为负）。
- **无批次可分摊**：补录早于任何批次的盘盈时，进入以调整单号为标识的临时批次，后续按 FIFO 被产出 / 销售消费；盘亏无可调整库存则忽略。

### 3.6 生产批次生命周期

- **创建**：`POST /production-batches` 生成 `BT-#####`，状态 `OPEN`、类型 `PRODUCTION`；批次日期与备注可改。
- **关联**：领用与产出必须选择 `OPEN` 批次；编辑可改批次，但原批次与新批次都必须 `OPEN`。
- **关闭**：`POST /production-batches/:id/close`；若批次待结转 > 0 且方木数量 ≤ 0，返回 409（`BATCH_PENDING_NO_STOCK`）；否则把待结转一次性转入本批次方木池，置 `CLOSED`、写 `closedAt`。折叠时关闭事件取「关闭时间」与「批内最晚单据日期」的较大值，确保关闭排在全部单据之后。
- **批量关闭**：`POST /production-batches/batch-close`，body `{ ids }`（去重、上限 200）；先查全部所选批次，非 `OPEN` 计入 `skipped`；对 `OPEN` 批次统一校验「待结转 > 0 且方木数量 ≤ 0」，任一命中即整批 409（错误信息带批次编号），不做部分成功；校验通过后 `updateMany` 置 `CLOSED` 并写 `closedAt`，返回 `{ closed, skipped }`。
- **锁定**：关闭后该批次的领用 / 产出不能新增、编辑或删除；批次日期 / 备注不能改；库存仍可销售。
- **期初批次**：`kind = OPENING`，设置期初方木时自动创建并置 `CLOSED`；不能挂领用 / 产出；若期初重新设置（开发环境），同步更新批次日期。
- **无删除**：批次不提供删除接口，避免历史单据失去归属。

## 4. 编号生成

- 原木领用 `MI-#####`：事务内取 `MI-` 前缀最大流水 +1，P2002 重试。
- 方木产出 `PR-#####`：同上。
- 生产批次 `BT-#####`：同上；期初库存批次与普通批次共用序列。
- 库存调整 `IC-#####`：同上；期初与盘点共用序列。
- 前缀登记见 `1-产品文档.md`「五、全局编号规范」。

## 6. 跨模块边界

- **只读聚合**：本模块为计算库存与成本，只读查询 `purchase_orders`、`sale_orders`、`sale_order_items`；不写对方表、不注入对方 Service。与 finance 应收应付只读聚合同一口径，避免 order → production → order 的模块环。
- **order → production**：OrderModule 导入 ProductionModule，保存销售单前调用 `calcSaleMaterialCost(items, excludeSaleCode?)` 获取批次扣层成本；ProductionModule 不导入 OrderModule。
- **purchase**：采购单保存即入库；本模块按送货吨数与采购合计金额聚合原木库存，采购单不写库存表。
- **finance**：库存估值与材料毛利不进入收支汇总；本期不做联动。
- **audit**：原木领用、方木产出与库存调整的写操作经全局审计拦截器落库。
