# 审计日志领域实现设计（audit）

> 定位：审计日志领域的**实现设计**（How）。需求见 `product/审计日志.md`（R-审计-001）。
> 全局约定见技术方案 §5（数据模型）/ §6（API 契约）/ §8.5（审计）；本文件只写本领域落点，不重述约定。

---

## 1. 模块结构与职责

```
modules/audit/
├── audit.controller.ts   # 只读查询接口
├── audit.service.ts      # 审计写入与查询（event_logs 数据主人）
├── dto/                  # 查询参数/响应契约形状
├── audit.module.ts
└── index.ts              # 唯一公开出口
```

- `event_logs` 表归 audit 模块（数据所有权）；写入由全局拦截器与 auth 显式调用 `AuditService`，读取由本模块 controller 提供。
- 采集是横切能力：`common/audit.interceptor.ts` 拦截写请求，`@AuditAction` / `@SkipAudit` 装饰器提供路由语义；拦截器只组装上下文，落库统一走 `AuditService`。
- 查询只读：不提供修改、删除、导出接口。

## 2. 数据模型概览

> 字段细节归 `packages/db/prisma/schema.prisma`（唯一事实源），此处只列新增概览。

在现有 `EventLog` 上新增可空列：

| 字段 | 用途 |
| --- | --- |
| `actor_role` | 操作发生时的角色快照 |
| `ip` / `user_agent` | 操作终端 |
| `method` / `path` | HTTP 方法与路径 |
| `status_code` | HTTP 状态码 |
| `error_code` | 统一错误码（如有） |
| `action_label` | 中文动作名，如「新建销售单」 |
| `object_code` | 对象编号快照，如 SO-00001 |
| `request_id` | 与技术日志关联 |

- 复用现有 `actor_id`、`actor_username`、`domain`、`action`、`object_type`、`object_id`、`result`、`payload`。
- 补索引：`(tenant_id, created_at)`、`(actor_id, created_at)`、`(domain, action)`。
- 迁移只加可空列与索引，不改历史数据；旧记录 `action_label` / `object_code` 为空时前端以 `domain / action` 兜底。
- 结果统一写 `ok` / `failed`；HTTP 状态放 `status_code`，旧记录的原始 `result` 原样保留。

## 3. 采集规则

- 新增 `@AuditAction({ domain, action, label, objectType })`：所有写接口显式声明领域、动作、中文名与对象类型；禁止依赖 URL 猜动作。
- 新增 `@SkipAudit()`：登录、登出、刷新令牌等需要显式处理或不应记录的接口使用。
- 拦截器：
  - 仅处理 `POST / PUT / PATCH / DELETE`；
  - 读取装饰器元数据；无元数据时回退现有路径解析，兼容旧接口；
  - `objectId` 优先级：`request.params.id` → 响应体 `id` → 请求体 `id`；
  - `objectCode` 取响应体 `code`；批量操作无单对象时为空，`payload` 记录 `count`；
  - 记录 `method/path/statusCode/errorCode/ip/userAgent/requestId`；
  - 成功写 `ok`，异常写 `failed`；异常的错误码从统一错误体读取（如有）；
  - 写入失败只写 pino 技术日志，不抛给业务。
- 守卫 403：写请求在 `AuthGuard` 被拒时拦截器不会执行，由守卫直接写一条 `failed`（`errorCode = FORBIDDEN`、`statusCode = 403`、`payload.requiredScopes`）；只对写方法记录，避免普通查看被拒产生噪音。
- IP 取 `x-forwarded-for` 第一个地址（生产代理）否则 `request.ip`；服务端入口设置 `trust proxy`，避免取到代理地址。

## 4. 身份操作

- 登录接口为 `@Public`，拦截器拿不到 `request.user`，因此：
  - `login` / `logout` / `refresh` 加 `@SkipAudit`，由 `AuthController` 显式调用 `AuditService`；
  - 登录成功：记录 `actorId`、账号名、角色快照、IP/UA，结果 `ok`；
  - 登录失败：记录尝试的账号名，`actorId` 为空，结果 `failed`，不记录密码；
  - 登出：`AuthService.logout` 在撤销前解析刷新令牌所属账号，返回操作者信息供 controller 记录；解析不到时记录匿名结果；
  - 修改密码：走拦截器，`objectType = user`，`objectId = request.user.userId`，动作名「修改密码」。
- 刷新令牌不记录，避免每 15 分钟产生噪音。

## 5. 打印 / 导出

- MCC 当前只有销售单打印，且为前端 iframe 打印，没有服务端文件产物。
- 新增 `POST /api/v1/sale-orders/{id}/print-events`：仅记录审计、无业务副作用；权限 `order:view`；返回 200 `{ id, code }`，供拦截器记录对象编号。
- 接口加 `@AuditAction({ domain: 'order', action: 'print', label: '打印销售单', objectType: 'sale_order' })`，由全局拦截器统一落库，避免重复手写。
- `PrintPreviewDialog` 在用户点击「打印」时调用，调用失败不阻塞打印；打开预览不计为打印。
- 未来新增导出时按同一模式提供领域专用记录端点，不提供通用客户端日志上报接口。

## 6. 查询接口

| 接口 | 路径 | 用途 |
| --- | --- | --- |
| list | `GET /api/v1/audit-logs` | 管理员查询审计记录（筛选 + 分页，时间倒序） |

- 查询参数：`page`、`pageSize`、`dateFrom`、`dateTo`、`actor`（账号名模糊）、`domain`、`action`、`result`；
- 响应：`items` + `total` + `page` + `pageSize`；不返回 `payload` 原文与任何敏感字段；
- 控制器加 `@RequireScopes('audit:view')`；
- 默认每页 20，最大 100；`dateFrom/dateTo` 由前端默认最近 30 天；
- 不提供详情、修改、删除接口。

## 7. 前端实现节（web）

- 路由 `/admin/audit-logs`，按 `product/平台布局.md` 列表页模式实现：筛选区 → 表格区 → 分页区；无页面标题、无多选、无批量操作。
- 筛选：时间范围（DatePicker）、操作人（Input，模糊）、领域（Select）、动作（Input）、结果（Select：全部 / 成功 / 失败）；查询 + 重置。
- 表格：时间、操作人、角色、动作、对象、结果、IP；`containerClassName="h-full overflow-y-auto"` + sticky 表头；空态「暂无审计记录」。
- 入口：`lib/nav.ts` 的 `platformNavItems` 增加审计日志（`ScrollTextIcon`、`scope: 'audit:view'`），`admin-shell.tsx` 头像下拉增加入口；仅管理员可见。
- 路由 scope：`scopeForPath('/admin/audit-logs')` → `audit:view`。
- 角色权限说明弹窗增加「审计日志」列（`audit:view`，无 manage）。
- 打印上报：`PrintPreviewDialog` 在打印按钮逻辑中调用 `POST /api/v1/sale-orders/{id}/print-events`，使用 `void` 不阻塞打印。

## 8. 测试

- 共享：权限矩阵包含 `audit:view` 且仅 ADMIN；审计查询 schema 边界。
- 服务端集成：登录成功/失败、写成功/失败、打印、筛选分页、非管理员 403、记录不含密码/令牌/请求体全文。
- 前端 E2E：管理员看到本人和其他账号的操作；销售直接访问被拒；打印产生审计记录。
- 审计只增不删，E2E 不清理审计行；用唯一时间戳/账号名筛选定位。
