
## 一、产品定位与目标

**定位与目标**：将家中小木材厂的业务和财务从当前无序状态，系统化、数字化，通过**自建数字化系统**承载；并为木包装等产业延伸、向同行业输出（SaaS）与 AI 能力引入留出扩展空间。

### 3.1 划分方法（判断新模块归属的四检验）

1. **名词法**：核心业务名词每个有且只有一个家；无家者应开新模块，两家相争说明划错；
2. **变更检验**：一个业务变化只应改动一个模块；
3. **业务对话检验**：业务人员的天然分工即领域边界；
4. **拿不准就合并**：数据所有权清晰前提下，模块内部后拆易，模块之间先拆难。

**反向警告**：不按技术分层划模块（不得出现 controller 模块 / service 模块）；不划太碎（正常 5~8 个，随领域数量）。

## 四、跨领域需求

本节只收**无单一主人域**的跨领域项。已有主人域的跨领域能力已归各自领域：账号、角色与权限见 `product/账号与权限.md`；平台布局与导航见 `product/平台布局.md`。

- **移动端（移动 Web）与适老化**（ADR-011）：现场操作类功能提供移动 Web 页面，不做小程序 / App；移动端独立设计，PC 不做适老化。决策见 ADR-011；使用端、移动页形态与适老化基线见 `product/平台布局.md`；技术落地见 `3-技术方案.md` §7.3。

- **【待补】** 税务与合规等跨领域要求；审计已归 `audit` 领域（见领域地图）。

## 五、全局编号规范

所有业务实体编号统一为「**域前缀 + 连字符 + 5 位流水**」，**不含年月日期**；系统生成、只读、永不复用，软删后不回收。流水在租户内按前缀全局递增，超出 5 位自然进位。

| 域 | 前缀 | 示例 | 说明 |
| --- | --- | --- | --- |
| 客户 | `CT` | `CT-00001` | 长期实体 |
| 供应商 | `SP` | `SP-00001` | 长期实体 |
| 采购单 | `PO` | `PO-00001` | 单头单据，无明细 |
| 成品销售单 | `SO` | `SO-00001` | 明细 = 主单号 + `-行序`，如 `SO-00001-01` |
| 资金账户 | `AC` | `AC-00001` | 对公 / 对私 / 票据账户 |
| 资金流水 | `CF` | `CF-00001` | 收款 / 付款 / 内部转账共用同一序列 |
| 租户 | `TN` | `TN-00001` | 长期实体；平台级全局流水，不按租户分段；仅用于平台运营展示与检索，不作为登录标识；创建后不可改 |
| 原木领用 | `MI` | `MI-00001` | 原木领用单，单头无明细 |
| 方木产出 | `PR` | `PR-00001` | 方木产出单，含产出明细 |
| 生产批次 | `BT` | `BT-00001` | 批次成本对象；期初库存批次也使用该序列 |
| 库存调整 | `IC` | `IC-00001` | 期初库存、盘盈、盘亏等库存调整单 |
| 包装方案 | `PD` | `PD-00001` | 包装方案编号；单元、图纸与版本共用主编号派生（`PD-00001-U01-01` / `PD-00001-R01`） |

- **只有登记过的前缀可用**：未建领域不预置前缀，随首个真实需求登记入本表；同一前缀不得复用。
- 各领域文档只登记本域前缀与派生规则，不重复定义格式（单一事实源）；生成实现见各领域 `design/` 与 `packages/shared` 纯函数。
- 历史数据重编号须与代码同批切换：先备份、停写，在同一事务内重排编号并同步引用（如流水的源单编号），同时输出「旧号 → 新号」对照表留档。
