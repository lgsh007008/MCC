
## 文档体系与优先级

**四层文档**：产品文档、ADR、技术方案、模块设计文档。

```
.AAAdocs/
├── 0-文档驱动开发机制.md            # 本文件（元文档）
├── 1-产品文档.md                    # 产品总纲（What：全局）
├── 2-adr.md                         # 架构决策记录（Why：只增不改）
├── 3-技术方案.md                     # 技术方案（How：全局）
├── product/<领域>.md                # 各领域需求（与 design 同名配对）
├── design/<领域>.md                 # 各领域实现设计（与 product 同名配对）
```


**优先级（冲突时以此裁决）**

```
产品文档（What/Why，需求与约束）
      ↑ 引用（R-xxx-NNN）
ADR  >  技术方案（全局约定）  >  模块设计文档（领域实现）
```

**说明**：ADR 最高；技术方案是其执行展开，并约束所有模块设计文档；各文档均自洽完整，不依赖任何外部讨论记录。

## 三条铁律

1. **正文只放当前真相**（现在是什么样），历史脉络走文末 changelog；
2. **单一事实源**：每条信息只在一处定义，他处只引用不复制（复制必漂移）；
3. **文档只放约定与指针**：技术细节（表结构、接口、AI 行为规则等）由代码或生成物承载，文档不重复定义，只写**概览 + 约定 + 详见 XX**

## 变更机制

本节机制对本文档体系下的**所有文档**均适用，所有文档都必须遵守。

新增、修改或删除决策 → 先更新对应文档的相应章节 → 在该文档 changelog 末尾**追加一行**（列：位置 / 类型 / 原本 / 现在 / 原因；类型仅取「新增」「修改」「删除」）。

**版本小节命名格式**：`v<YYYYMMDD>`，如 `v20261015`。同一天只对应一个小节，新的一天即新的版本小节。

**纪律**：changelog 只增不改——已写入的历史行**不得修改**，变更只能新增：跨天在文末**追加新的版本小节**，同一天则在当日小节内末尾**追加新行**。

## 文档定位

### 产品文档

- **回答**：What/Why——需求、约束、验收标准、**页面设计**。
- **位置与拆分**：`1-产品文档.md` 为全局总纲；各领域需求在 `product/<领域>.md`，与 `design/<领域>.md` 同名配对。
- **关键规则**：需求编号 `R-xxx-NNN` 在此定义，供他文档引用；业务结构（领域地图 / 模块清单）与领域划分方法在总纲维护。

### ADR

- **回答**：为什么定死——不可逆的架构决策。
- **位置与拆分**：`2-adr.md` 单文件，按 `ADR-NNN` 分节。
- **关键规则**：只增不改——决策被取代时新增新条，不回头改旧条；优先级最高，冲突时以此裁决；每条自洽完整，不依赖外部讨论记录。

### 技术方案

- **回答**：全局怎么做——跨模块的约定、边界、规范。
- **位置与拆分**：`3-技术方案.md` 单文件。
- **关键规则**：全局约定的唯一出处，被所有模块设计文档引用。

### 模块设计文档

- **回答**：该领域具体怎么做——表结构、接口清单、状态机、算法与关键流程。
- **位置与拆分**：`design/<领域>.md`，**每领域一份**，与 `product/<领域>.md` 同名配对；主体为**后端**设计（数据模型细节、接口清单、状态机、算法与关键流程），另含**前端实现节**。
- **关键规则**：需求是改它的动作，不是它的单位——一个需求通常只更新一份（跨模块时更新多份），**不新增文件**。

## 前端与页面内容的归属

### 页面设计（属产品文档）

- 页面设计（这一页要有什么、怎么排、怎么交互）**归产品文档**（`product/<领域>.md`），作为对应需求的一部分——需求改则页面随之改，天然同步。
- 与前端实现的区别：页面设计=设计意图（人写，属 What）；前端实现=技术落地（AI 写，属 How）。

### 前端实现节（属模块设计文档）

本领域在**前端侧的技术落地设计**——回答前端代码怎么组织，而不是页面长什么样；它是页面设计（产品文档）与前端规范（技术方案 §7）之间的翻译层。**只在存在非平凡前端逻辑时写**（纯 CRUD 页面用现成组件拼即可，不为它单开一节）。

### 跨模块页面（归属与接口引用）

- **页面归属唯一**：一个页面必须且只能归属一个领域——判定看它**围绕哪个实体 / 业务动作**展开（如订单详情页虽展示报价与生产信息，主实体是订单，归 `order`）；拿不准时用**变更检验**（该页面会随哪个领域的需求变化而改）。**一个页面只能在一份文档里被描述**，禁止两份各写一半（否则即成两份真相）。
- **接口引用可跨模块**：数据来源项列出该页面调用的**所有**接口并标注归属领域，**只引用、不重述定义**（定义留在各领域的接口清单）。
- **数据聚合**：优先**客户端并发调用 + 客户端组合**；聚合逻辑复杂或需权限裁剪时，由**页面所属领域**提供**只读聚合接口**，内部只调其他领域的公开接口。
- **禁止**：新建聚合模块直接读他领域的表——属边界穿透，违反 ADR-001。
